## 二、需求转写与目标边界

### 2.1 目标软件一句话定义

> 一个 **Java 21、Maven 多模块、依赖最小化**的 Agent 运行时：以一个大 Agent（"大脑"）为核心，可**自由创建/销毁多个权限各异的子 Agent**；对外用 **MCP**（工具/数据）、**A2A**（Agent 间互操作）、**AG-UI**（用户界面）说话；对内用**统一事件存储 + 个人信息模型 + 权限/身份**把一切状态管起来；并且**运行时自身（配置、模块、skills、子 Agent）可被运行中的 Agent 管理**。

### 2.2 需求拆解（每个词都对应一个"注意面"）

| 需求词 | 转写 | 对应注意面 |
|---|---|---|
| Java | 延续 Java 21 + Maven 工程习惯 | 技术栈章节（JDK21 特性、发行、沙箱） |
| 多代码模块 | Maven 多模块、单向依赖、模块化扩展 | 工程与模块接缝设计 |
| 兼容通用协议 | MCP/A2A/AG-UI/ACP/Skills/AGENTS.md | 协议栈章节（各协议 Java 支持现状与风险） |
| 自由创建子 Agent | 子 Agent 模板 + 运行时注册表 + 生命周期 API | 子 Agent 模型章节 |
| 权限不同 | 每 Agent 权限集（工具白名单/参数范围/身份凭证） | 权限与身份章节 |
| 能干的大 Agent | 自研推理循环 + 上下文构造 + 模型路由 | 大 Agent（Brain）章节 |
| 一切可被 Agent 管理 | 配置即数据 + 自管理工具 + 权限单调性约束 | 自管理闭环章节 |
| 轻量化 | 依赖最小化、启动快、内存省、可懒加载 | 轻量化章节（贯穿全部） |

### 2.3 边界判断：什么必须自研、什么绝不自研

用户材料的第七节结论经核实**仍然成立**，是本项目的技术边界：

**绝不自研（有现成标准 + 官方/社区 Java 路线）：**
- Agent↔工具/数据 → MCP（官方 Java SDK，Tier 2，见协议栈章节的修正）；
- Agent↔Agent → A2A（v1.0 已 stable，官方 Java SDK，client+server 三传输）；
- Agent↔用户/应用 → AG-UI（Java SDK 存在但为社区级，见协议栈章节的修正）；
- Editor↔Coding Agent → ACP（Java SDK 0.x 可用，二期）；
- 能力打包 → Agent Skills（规范稳定，用户已有实践）；
- 项目上下文约定 → AGENTS.md（用户已有高质量实践）。

**必须自研（没有任何主流协议/软件替你解决）：**
1. **个人信息模型**（Person/Project/Conversation/Entity/Event/Observation/Claim/Evidence/Thought/Decision/Task/Intent/Relationship/Document/Session/WorldState 的实体关系）——GSimulator 的 World/Node/Checkpoint/Element + `@` 引用是用户自己的雏形；
2. **统一事件存储**（append-only 事件日志 + 快照 + 检索）——GSimulator 的 EventBus/GSimEvent 只是内存版雏形，缺持久化与查询；
3. **权限与身份**（每 Agent 的最小权限集、凭证发放、审计）——iBotMosire 三级 token 与 GSimulator 工具声明体系是起点，但缺 per-Agent 细粒度；
4. **上下文构造**（会话历史 + 记忆检索 + skills 元数据 + 项目上下文 + 工具目录的组装与压缩）——Hermes micro-compaction、Letta memory-first 是参照。

### 2.4 三个空目录的最自然映射（推测，待用户确认）

- `AgentLibMosire`：Agent 公共库——协议适配（MCP/A2A/AG-UI）、工具注册与 Guard、权限模型、事件总线、模型路由、子 Agent 模板。迁移来源：GSimulator `gsim-agentsmanager` 的 tool/event 包 + iBotMosire-core。
- `BrainMosire`：大 Agent——推理循环（ToolLoop）、上下文构造、子 Agent 编排、记忆。迁移来源：GSimulator `AbstractAgent`/`AgentsManager`/`llm` 包。
- `MainMosire`：主程序/网关——进程组装、协议入口、配置加载、健康检查、发行。迁移来源：iBotMosire-gateway + GoatMosire 静态服务。

（该映射与子调查 D 的"迁移映射"结论一致。）

### 2.5 与既有实践的关系（一句话）

用户手里已有一个**可运行的"主 Agent + 权限化子 Agent + 手写 MCP + 事件流 + 自管理配置"的原型集群**；新项目的主要工作是**剥离业务耦合、以官方 SDK 替换手写协议、补 A2A/AG-UI/ACP 与进程级沙箱**，而不是从零设计。细节见第六章。
