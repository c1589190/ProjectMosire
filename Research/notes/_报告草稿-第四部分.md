### 3.1 MCP（第一优先级）

**规范现状**：当前版 2026-07-28（2026-07-28 GA，"史上最大更新"）。关键变化已逐条核实：
- **无状态核心**：废除 initialize/initialized 与 Mcp-Session-Id；每请求自带协议版本+客户端能力（`_meta`），服务器 `_meta` 返回 serverInfo；可选 `server/discover`；版本不匹配返回 -32022。
- **MRTR**：取代服务端反向请求（roots/sampling/elicitation 的旧机制），结果带 `resultType`（complete / input_required）。
- **Header 路由**：`Mcp-Method`/`Mcp-Name` 头，网关按头路由/授权。
- **可缓存列表**：ttlMs + cacheScope + 确定性排序。
- **授权加固**：RFC 9207 issuer 校验；DCR 弃用 → CIMD。
- **正式扩展框架**：Tasks 移入 `io.modelcontextprotocol/tasks`；`subscriptions/listen` 取代旧 GET 通知端点。
- **弃用（新代码禁用）**：Roots、Sampling、Logging、legacy HTTP+SSE、ping、logging/setLevel；12 个月最低弃用窗口。

**Java SDK 现状（对原始资料的重要修正）**：官方 SDK（`io.modelcontextprotocol.sdk:mcp-bom`，v2.0.1，2026-08-19）**是 Tier 2 而非 Tier 1**（Tier 1 = TS/Python/C#/Go/Rust）。模块：mcp / mcp-core（无 JSON 库绑定）/ mcp-json-jackson2 / mcp-json-jackson3 / mcp-test。Transport：stdio + Streamable HTTP + stateless（HttpServletStatelessServerTransport）client/server 齐全。API：`McpServer.sync/async(transport).serverInfo(...).capabilities(...).build()` + `addTool`。Conformance：server 40/40、client 9/10。

**落点**：
- 角色双要：Brain 作为 MCP **client** 调外部工具/数据；我们的模块能力包装为 MCP **server**。
- 起步锁 2.0.1；2.x 已含 stateless 形态；2026-07-28 全量支持在 3.x（首个 milestone 计划 2026-09）——升级列入技术债务。
- 风险中：规范刚大改，生态迁移期；老客户端（如旧 Claude Code）仍需 2025 握手回退（iBotMosire 已设计此策略）。
- 与 iBotMosire 手搓层的关系：保留"ToolRegistry 与协议层解耦"原则，协议实现换官方 SDK；iBotMosire 的 `mcp.mode=hand-rolled|sdk` 开关可保留为降级手段。

### 3.2 A2A（第一优先级，子 Agent 互操作的标准答案）

**规范现状**：v1.0.0 于 **2026-03-12** 发布（原始资料一致），当前 v1.0.1；172 家组织（Partners 页实测）；2026-08-27 加入 LF AAIF。规范本体 = `a2a.proto`（ProtoJSON）+ JSON/REST 绑定。Agent Card 必填：name/description/version/capabilities/defaultInputModes/defaultOutputModes/skills/supportedInterfaces；可选 provider/signatures（JWS 签名卡）等。TaskState 9 态（submitted/working/input-required/auth-required/completed/canceled/failed/rejected/unspecified）；artifacts（TextPart/FilePart/DataPart）；push notification（webhook 订阅）。

**Java SDK 现状**：`org.a2aproject.sdk`，**1.3.1.Final**（2026-09-03），Apache-2.0。client（零 jakarta 依赖）+ server-common + transport{grpc,jsonrpc,rest} 三传输 client+server 齐全，附 TCK。**注意：server-common 依赖 CDI（jakarta.enterprise/jakarta.inject），参考实现绑 Quarkus**——轻量路线需决策：接受 CDI 换取完整合规，或手写最小 JSON-RPC HTTP 绑定（有手搓 MCP 经验，但"手搓协议"教训要记取）。

**落点**：
- 角色双要：主 Agent 对外 = A2A **server**（Agent Card 描述能力）；调子 Agent/外部 Agent = A2A **client**。
- 先 JSON-RPC 传输起步（生态最通用）；gRPC/REST 按需后补。
- **这是"自由创建多个权限不同的子 Agent"的对外互操作面**：子 Agent 可以是进程内实例，也可以是远程 A2A peer（Hermes/Codex/其他 Agent 软件）——同一抽象。

### 3.3 AG-UI（用户界面出口，P1）

**规范现状**：**1.0 仍 Draft（未定稿）**；事件 8 族：Lifecycle（RUN_STARTED/FINISHED/ERROR、STEP_*）、Text Messages（START/CONTENT/END）、Tool Calls（START/ARGS/END/RESULT）、Reasoning、State（SNAPSHOT/DELTA）、Activity（JSON Patch）、**Subagents（SUBAGENT_STARTED/FINISHED/ERROR + subagentRunId）**、Passthrough。**标准传输只有 HTTP+SSE（必）与 HTTP+Protobuf（可选）；WebSocket 仅为自定义传输**（对原始资料的修正）。0.x 的 MetaEvents 已并入基础 Metadata。

**Java 支持**：存在但**社区级**：`sdks/community/java`（core/client/server 三模块，Apache-2.0，Java 17+，core 零依赖用 Flow.Publisher），Maven Central 坐标 `com.ag-ui.community:java-core/java-client/java-server` 0.1.0（docs 页的旧坐标已过时）；一等 SDK 只有 TS/Python/.NET。

**落点**：
- 我们做 **server** 角色；前端/桌面壳不在范围内。
- 风险高（规范 Draft + SDK 0.1.0 + 社区维护）→ 隔离在薄适配层后；**手写兜底的最小事件子集**：RUN_STARTED → TEXT_MESSAGE_START/CONTENT*/END →（可选 TOOL_CALL_*、STATE_*）→ RUN_FINISHED + RunAgentInput 解析 + RUN_ERROR，SSE 直出（我们有 SSE 经验，事件模型简单）。
- Subagents 事件族与我们"子 Agent 树"天然对齐——UI 可原生展示子 Agent 归属/并行/终止。

### 3.4 ACP（P2 可选）

- 规范：v1 = Latest（发起方 Zed + JetBrains），v2 = Draft；本地 **stdio JSON-RPC 必支持**，远程 HTTP/WebSocket 官方标注 WIP。
- 方法名修正：权限是 **`session/request_permission`**（非 permission_request）；v1 无 plan/streaming（plan 走 session/update 的 Plan 条目）。
- 官方 Pure Java SDK：`com.agentclientprotocol:acp-core` **0.17.0**（annotation/sync/async 三风格、stdio+WebSocket-Jetty）——原始资料该条全部属实。
- 落点：仅当我们想被 Zed/JetBrains/编辑器接入、或接入外部 coding agent 时启用 agent 角色。P2。

### 3.5 Agent Skills 与 AGENTS.md（P0 基础能力）

- **Skills**：SKILL.md frontmatter（name 必填且须与目录名一致、description 1-1024 字符；可选 license/compatibility/metadata/allowed-tools[实验]）+ scripts/references/assets；渐进披露三档（catalog ~50-100 token/技能 → 激活载正文 <5000 token → 引用资源按需）。无 SDK，自实现目录扫描 + YAML 解析 + 三档加载。**`allowed-tools` 直接映射为子 Agent 权限**（如 `Bash(git:*) Bash(jq:*) Read`）。
- **AGENTS.md**：纯 Markdown、无必填字段、支持嵌套、最近文件优先；60k+ 仓库采用、LF/AAIF 托管。落点：① 我们每个模块仓库提供 AGENTS.md；② 操作第三方仓库时优先读取并遵守。
- 用户已有实践：TanwenResearch 的 SKILL.md（含伦理边界/六步工作流/references 渐进披露）、GSimulator AGENTS.md（连接/概念/命名空间/分页/@ 引用）——直接沿用风格。

### 3.6 MCP Apps / A2UI（P2）

- **MCP Apps**：2026-01-26 成为**第一个正式 MCP 扩展且 production-ready**（官方博客核实）；机制 = 工具 `_meta.ui.resourceUri` 声明 `ui://` 资源 → 宿主沙箱 iframe → JSON-RPC over postMessage 双向通信；宿主矩阵已覆盖 Claude/VS Code/Goose/ChatGPT 等。**无官方 Java 库**，但 server 侧只需基于 MCP Java SDK 手工加 `_meta.ui` + ui:// 资源端点。适合给工具提供交互面板（如 Minecraft 控制台、地图）。
- **A2UI**：v0.9.1 生产 / v1.0 Candidate；消息为 createSurface/updateComponents/updateDataModel/deleteSurface（surfaceUpdate/dataModelUpdate 是 v0.8 旧名）；纯 JSON 生成，无 SDK 需求。观察 v1.0 定稿。

### 3.7 不碰与参考

- **ANP**：1.1 版，早期、采纳少——观察不绑定（用户材料判断正确）。
- **老 IBM ACP**：2025-08-27 归档、"ACP is now part of A2A"——禁用。
- **AutoGen**：maintenance mode；后继 **Microsoft Agent Framework**（MIT，.NET/Python 全功能 + Go，A2A/MCP 原生，**无 Java**）——仅参考其编排/skills/安全 ADR 思想。

### 3.8 原始资料声明核查结果摘要（详见 notes/protocol-stack.md §11）

- 完全核实：MCP 2026-07-28 大改全部子项、A2A v1.0 日期与 150+（实为 172）组织、A2A Java SDK 三传输、ACP 纯 Java SDK、MCP Apps 首个正式扩展、老 ACP 归并、AutoGen maintenance、AGENTS.md/Skills 规范。
- 部分修正：MCP Java SDK 是 **Tier 2** 非 Tier 1；AG-UI 传输无标准 WebSocket、MetaEvents 已并入 Metadata；ACP 方法名 `session/request_permission`；A2UI 消息名为 v0.9 命名。
