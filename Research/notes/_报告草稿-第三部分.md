## 八、主要风险与坑（写这个 Agent 最容易踩的地方）

### 8.1 协议/SDK 成熟度风险

1. **MCP Java SDK 是 Tier 2，且版本滞后半个规范代**：Tier 1 是 TS/Python/Go/C#（2026-07-28 GA 公告明列）；Java SDK 2.0.x 追踪 2025-11-25，2026-07-28（stateless core/MRTR/header 路由）支持在 3.x、首个 milestone 计划 2026-09。
   → 起步锁 2.0.x 稳定线；协议形态按 2026-07-28 设计；把"升级 3.0"列入技术债务清单；保留 iBotMosire 式 `hand-rolled | sdk` 开关兜底。
2. **AG-UI Java SDK 只有社区版 0.1.0（JitPack 发布）**：可用作参考/白名单引入，但生产上要有手写 SSE 事件映射的 fallback（事件模型简单、我们有 SSE 经验）。
3. **ACP Java SDK 还是 0.16.0**：API 尚在演化（协议本体已稳定为 version 1）。二期再用，不要在核心上绑定。
4. **A2UI 是 early preview**（v0.9.1 生产 + v1.0 RC）：不要在一期依赖；MCP Apps 是更成熟的"工具自带 UI"路线（正式 MCP 扩展）。
5. **ANP/UCP/AP2**：观察不绑定；尤其 ANP 概念诱人但采用度低。

### 8.2 协议演进本身的坑

6. **MCP 规范半年一大改**：2026-07-28 起 Roots/Sampling/Logging 已弃用、legacy HTTP+SSE 一年退场——新代码绝不能依赖这些；所有"面向 2026 规范的参考实现"（含 iBotMosire 手搓层）都要随 3.x SDK 重审。
7. **命名混淆坑**：ACP 现在默认指 Agent Client Protocol；IBM 老 ACP（Agent Communication Protocol）已归并 A2A 并归档——查资料时注意时间戳。
8. **GSimulator 手写 MCP 硬编码 2024-11-05 无版本协商**（WDMosire 已批评并做了"版本封顶回显"）：新项目用官方 SDK 直接消灭此类问题；若保留手搓层必须实现版本协商。

### 8.3 Java 平台特有的坑

9. **SecurityManager 已被移除**：Java 没有进程内安全沙箱了 → 子 Agent 隔离的现实解是**进程级**（stdio 子进程 + OS 沙箱如 bwrap/容器），进程内"逻辑隔离"只能防君子。这是权限模型设计的硬约束。
10. **GraalVM native image 与反射型库的兼容成本**（Jackson/Netty 等需配置）——轻量化发行先走"JVM + AppCDS + shade jar"路线，native 作远期选项（子调查 C 核实后定稿）。
11. **虚拟线程的 pin 风险**：synchronized 块内阻塞 I/O 会 pin 载体线程——工具执行/LLM 流解析代码要避免在锁内做阻塞调用。
12. **子进程泄漏**：Agent 子进程必须进程树级清理（iBotMosire 已有 SIGTERM→超时→destroyForcibly 模式），否则防跑飞形同虚设。

### 8.4 自管理带来的坑

13. **权限单调性**：Agent 可改自身配置 → 必须强制"任何 Agent 不能授予自己/其子 Agent 超过自身拥有的权限"，且自管理工具本身要分级（谁能创建/删除谁的配置）。GSimulator 的子 Agent 配置 CRUD 目前没有这个边界，是第一个要补的。
14. **自升级禁令**：Agent 可以管理配置/skills/子 Agent，但**不能替换自己的二进制/升级运行时**（升级走外部流程），否则一次坏更新=自杀。
15. **配置写坏的兜底**：原子写（tmp+ATOMIC_MOVE，GSimulator 已有）+ schema 校验 + 最近一次已知良好配置（last-known-good）回退 + 所有变更入事件日志（可审计可回放）。

### 8.5 安全坑

16. **Prompt injection 是常态而非例外**：工具返回内容（网页、消息、文档）一律不可信；高危工具白名单 + 参数范围 + 干跑预览；"工具输出里的指令"要当数据处理。GSimulator 的反幻觉护栏（伪造 [TOOL_RESULT] 拦截）是第一道经验。
17. **凭证平面**：LLM provider key/账号 token 与"Agent 可见数据"分离；每子 Agent 独立最小凭证，不做共享 system token（iBotMosire 单 default token 模式在"多子 Agent"下必须升级）。
18. **网络暴露面**：MCP/A2A/AG-UI 默认绑 127.0.0.1；对外开任何口都要独立授权与限流。

### 8.6 数据与记忆坑

19. **事件存储 schema 演进**：个人信息模型是长期资产，事件/实体 schema 必须版本化 + 迁移工具（Hermes 的 state_schema/repair 经验：坏了要有修复工具）。
20. **上下文膨胀**：工具结果溢出（GSimulator 暂存 docId 模式）、工具目录分页/工具组激活（GSimulator 模式）、micro-compaction——三者都要，否则大 Agent 很快被塞爆。
21. **"假推送"教训**：GSim/WDMosire 的 SSE 是假推送，iBotMosire 明确指出 subscriptions/listen 真推送是手搓层唯一复杂点——事件流从第一天就按真推送设计（AG-UI/A2A 的流式语义都要求真推送）。

### 8.7 生态与合规坑

22. **许可证**：采用的 SDK（MCP MIT / a2a-java Apache-2.0 / ACP Apache-2.0 / AG-UI community Apache-2.0）全部宽松；Dify、Open WebUI 带附加条件——只借鉴设计不抄代码；借鉴 Hermes/OpenCode/Codex 时同样核对 LICENSE（Hermes MIT、Codex Apache-2.0 等，逐仓库确认）。
23. **社区数字不可靠**：stars/MAU 无法完全核实，本报告一律标注证据等级；不要用"242k stars"之类作为技术选型论据，要看源码与 SDK 生态。
24. **AutoGen 已 maintenance**：不要以 AutoGen 为基础（后继 Microsoft Agent Framework，且无 Java SDK——Java 侧只能用其思想）。

### 8.8 工程坑

25. **模块依赖方向必须钉死**（core 不依赖 agent、UI 不依赖 core 之类），沿用"import 零命中 + pom 无依赖边"的双重检查（GSimulator CLAUDE.md 的判定法）。
26. **测试要离线**：Mock 模型、假 Agent 子进程（iBotMosire FakeAgentAdapter 模式）、事件重放——任何测试依赖外部 LLM 都会把 CI 变成彩票。
27. **协议合规可测**：MCP conformance tests、A2A TCK 接进 CI，避免"手搓又搓歪"（三代手写 MCP 的历史教训）。
