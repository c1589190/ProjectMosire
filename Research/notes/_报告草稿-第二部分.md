## 六、既有实践盘点：你手里已经有什么

### 6.1 结论先行

在 `~/DevMosire` 下，用户已经拥有一个**可运行的"主 Agent + 权限化子 Agent + 手写 MCP + 事件流 + 自管理配置"原型集群**。新项目不是从零设计，而是：**剥离业务耦合 + 用官方 SDK 替换手写协议 + 补 A2A/AG-UI/ACP 与进程级沙箱**。

### 6.2 两个核心资产项目

#### GSimulator（`gsim-agentsmanager` 模块 = 事实上的 Agent 运行时库）
- **AgentTool 工具接口**（name/description/JSON Schema/execute + 权限自声明）→ AgentLibMosire 的底稿；
- **ToolExecutionGuard**：执行入口的最终可信边界（"不能认为没注入给模型就等于无法执行"）；
- **ToolGroupManager** + `activate_tool_groups`：工具组按需激活（上下文瘦身手段）；
- **EventBus/GSimEvent**：`(sessionId, taskId, type, time, data)` 事件词汇表已接近 AG-UI（tool_started/tool_done/llm_delta/run_stage…），CLI 与 SSE 消费同一条流；
- **AgentConfigManager**：`agents/*.json` 一个文件一个 Agent，运行时 CRUD + tmp→ATOMIC_MOVE→reload 原子生效；**主 Agent 经 MCP 工具 create/update/delete_sub_agent_config + dispatch_sub_agent 自管理子 Agent——"Agent 自管理"的现成先例**；
- **AbstractAgent ToolLoop**：反幻觉护栏（伪造 [TOOL_RESULT] 拦截、finish_action 强制收尾、连续空轮中止）、工具结果溢出暂存 docId；
- **LlmClient 依赖反转 + SseParser**：OpenAI 兼容流 + 国产变体 + JSON fallback；
- **子进程监督**（iBotMosire 侧）：ProcessBuilder + 双虚拟线程 + SIGTERM→超时→进程树 destroyForcibly。

#### iBotMosire（2026-08 定稿设计 = 新项目最近的前作蓝图）
- 5 模块单向依赖拓扑（core ← napcat/agent ← gateway；qqws 独立进程）；
- **权限模型**：Bearer token → guest/default/system × 工具三要素（requiredLevel/sensitive/destructive），逐请求校验、拒绝即终局、无审批流、任何工具都不能关进程；
- **手搓 2026-07-28 Streamable HTTP MCP**：server/discover、Mcp-Method/Mcp-Name 头、-32020 头体校验、subscriptions/listen 真推送、tools/list_changed 动态注册推送；`mcp.mode = hand-rolled | sdk` 一键切换预留；
- **进程隔离理由**：system 级 Agent 不能接触 Client 终端账号 → QQWS 独立进程 + role:client 账号保留；
- AgentAdapter 抽象（ClaudeCode/OpenCode 两个实现 + FakeAgentAdapter 测试件）；
- 防跑飞硬顶：maxTurns=20 / maxToolCallsPerTurn=30 / timeBudget=10min。

### 6.3 共性工程约定（直接照搬）

- Java 21 + Maven 多模块单向依赖 + 纯 JDK（jdk.httpserver + 虚拟线程，不上 Spring）；
- 依赖最小三件套：Jackson + SLF4J/Log4j2 + OkHttp；shade 单 fat JAR；外部 config/ 模板；
- Spotless→Checkstyle→SpotBugs 门禁；record 防御性拷贝；中文 Javadoc + ARCHITECTURE/DEVELOPMENT_PLAN 双文档 + **决策日志表**；
- /health 端点；状态查询=最低权限；离线可测（FakeAgentAdapter/MockNapCatServer）。

### 6.4 Skills 与 AGENTS.md 实践（已符合标准）

- TanwenResearch `skills/tanweng-persona/`：SKILL.md frontmatter + references/ 渐进披露 + scripts/ 校验脚本 + 硬边界声明——**已是标准 Agent Skills**；
- GSimulator `skills/`（dual-character-sim 等，带 category/tags）；
- GSimulator `AGENTS.md`：面向外部 Agent 的接入指南（连接方式/核心概念/工具命名空间/分页约定/@ 引用系统）——**质量很高，可直接作为新项目的 AGENTS.md 范本**。

### 6.5 必须新做/不能照搬的缺口（子调查 D 结论，主笔确认）

1. **A2A / AG-UI / ACP 完全空白**；
2. **手写 MCP 协议层应换成官方 Java SDK**（现手写停 2024-11-05 或 2026-07-28 tools 子集，缺 prompts/resources/完整 streamable HTTP）；保留"ToolRegistry 与协议层解耦"原则与 ToolRegistryMcpAdapter 的适配经验；
3. **进程级沙箱缺失**：现有隔离=独立进程+权限门，无 OS 级沙箱（容器/bwrap/目录 jail/网络限制）；
4. **身份授权仅静态 token→等级**：无 per-Agent 细粒度凭证、无审计、无 OAuth/OIDC；
5. **无统一事件存储**：JSON 文件/环形缓冲级方案，append-only event log + 检索是空白；
6. **自管理配置的权限边界缺失**：GSimulator 的子 Agent 配置 CRUD 没有"谁可以改谁的配置"边界；
7. **多进程协同基础设施**：无进程间生命周期管理通用件（拉起/心跳/优雅退出）。
