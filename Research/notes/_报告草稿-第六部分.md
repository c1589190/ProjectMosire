## 七、跨切面注意点总表（本报告的核心答案）

"写这样一个 Agent，需要注意哪些方面"——按切面组织，每个方面给：**注意什么 / 为什么 / 依据与参照 / 对轻量化的影响**。

### 7.1 架构与模块边界
| 注意点 | 说明 | 依据 |
|---|---|---|
| core 窄腰、能力在边缘 | 核心只做循环/状态/权限/事件；工具=注册表、能力=MCP 子进程/插件/skills，按需加载 | Hermes "narrow waist"；Goose MCP-first |
| headless server + UI 可选 | core 是无 UI 服务进程（OpenAPI + SSE）；TUI/Web 是可选模块 | OpenCode serve 模式 |
| Maven 模块单向依赖 | 依赖方向写死并双重检查（import 零命中 + pom 无依赖边） | GSimulator CLAUDE.md 判定法 |
| 协议层与工具注册表解耦 | MCP/A2A/AG-UI 只是 AgentTool/ToolRegistry 的适配器，可替换、可切换 | iBotMosire 设计原则 |
| 三目录映射 | AgentLibMosire（库）/BrainMosire（大脑）/MainMosire（网关组装） | 子调查 D 迁移映射 |

### 7.2 协议集成
| 注意点 | 说明 | 依据 |
|---|---|---|
| P0 只做 MCP+A2A+Skills+AGENTS.md | 全部有成熟 Java 路线或零 SDK 成本 | 子调查 A 优先级表 |
| MCP Java SDK 锁 2.0.1（Tier 2） | 2.x 追 2025-11-25；2026-07-28 全量在 3.x（预计 2026-09）→ 升级列入债务；保留 hand-rolled 开关兜底 | 一手抽查 + A |
| 新代码禁用弃用特性 | Roots/Sampling/Logging/legacy HTTP+SSE 已弃用；按 2026-07-28 形态设计（无会话、server/discover、subscriptions/listen） | A |
| A2A 用官方 SDK，先 JSON-RPC | server-common 带 CDI 依赖（Quarkus 风格）——先 SDK 换合规+TCK；重量不可接受再手写最小 HTTP 绑定 | 一手抽查 + A |
| AG-UI 隔离在薄适配层 | 规范 Draft + 社区 SDK 0.1.0 → 薄适配层 + 手写最小事件子集兜底（SSE 直出） | A |
| 事件面设计成 AG-UI 兼容 | 现成平台（n8n/Dify/OpenWebUI）反而都不支持 AG-UI——我们先兼容就是差异化 | B |
| 名字混淆坑 | ACP=Agent Client Protocol；老 IBM ACP 已归并 A2A 禁用 | A |

### 7.3 子 Agent 模型
| 注意点 | 说明 | 依据 |
|---|---|---|
| 子 Agent = 数据不是代码 | JSON Schema 校验的模板（description/prompt/model/工具白名单/权限映射/steps/超时）+ 目录扫描；可被 Agent 自管理 | OpenCode；GSimulator agents/*.json 同构先例 |
| spawn API 字段 | goal/context/role/allowed_toolsets/blocked_tools/working_directory/timeout + depth 限深 + 完整状态机 | Hermes SubagentLaunchRequest |
| 权限单调性 | 默认继承父级、可逐项收紧；子 Agent 永远不能提权（防递归 delegate、防越权） | OpenCode/Hermes/Goose/Letta 一致做法 |
| 隔离四档 | permission 映射 → 工具白名单 → 只读 agent → 子进程/OS 沙箱；预留 Executor 抽象（本地/子进程/容器切换） | B 综合 |
| 子 Agent 可以是外部进程 | stdio MCP 子进程形态 = 天然沙箱边界；外部 coding agent（claude-code/codex）也是"一个子 Agent" | iBotMosire Adapter 模式 + Goose 外部 subagent 模式 |
| 防跑飞硬顶 | maxTurns/maxToolCallsPerTurn/timeBudget + 进程树清理 + 配额记账 | iBotMosire 设计 |

### 7.4 大 Agent（Brain）
| 注意点 | 说明 | 依据 |
|---|---|---|
| 主循环 = tool-calling + 事件流记录 | 每轮：装配上下文 → LLM → 执行工具 → observation 回流 → 记录事件；直到停止/上限 | OpenCode/Codex/Goose 事实标准 + OpenHands event-sourced |
| 上下文构造四来源 | 会话历史 + 记忆检索（FTS）+ skills 目录（渐进披露）+ AGENTS.md/项目上下文 | Hermes/Letta/OpenCode |
| 隐藏系统 agent 做压缩 | compaction/title/summary 是配置化的 LLM 流水线，非硬编码 | OpenCode |
| prompt-cache 不变量 | 历史只在压缩时可变；配置修改默认延迟生效 + --now | Hermes 铁律 |
| 反幻觉护栏 | finish_action 强制收尾、伪造 [TOOL_RESULT] 拦截、连续空轮中止、孤儿 tool_call 剥离 | GSimulator AbstractAgent（现成件） |
| 工具结果溢出治理 | 超限暂存 docId 回传引用，防上下文爆炸 | GSimulator 现成件 |

### 7.5 权限与身份
| 注意点 | 说明 | 依据 |
|---|---|---|
| 双维权限模型 | 身份维（token→guest/default/system）+ 工具维（requiredLevel/sensitive/destructive）+ **per-Agent 维（工具白名单/参数范围）** | iBotMosire + GSimulator 组合 |
| 执行入口才是最终边界 | "没注入给模型≠不能执行"——Guard 在 tools/call 层强制校验 | GSimulator ToolExecutionGuard |
| 每子 Agent 独立最小凭证 | 不再共享单 default token；凭证平面与 Agent 可见数据分离 | 多子 Agent 升级要求 |
| 拒绝即终局 vs 审批流可插拔 | 默认拒绝即终局（无审批流）；PermissionGate 接口可插拔（CLI 确认门/AG-UI HITL/auto-approve） | iBotMosire + GSimulator CliToolPermissionGate |
| 凭据目录写硬阻断 | ~/.ssh、.env、mcp-tokens 等永远不进工具可写范围 | Hermes |
| 任何工具都不能关进程 | 进程停止只能 OS 信号 | iBotMosire 硬规则 |

### 7.6 自管理闭环
| 注意点 | 说明 | 依据 |
|---|---|---|
| 配置即数据 | 全部配置（agent 模板/白名单/模型/skills 索引）是可读写 JSON 文档，带 schema | OpenCode $schema + GSimulator 实践 |
| 六要素闭环 | schema 校验 → 原子写（tmp+ATOMIC_MOVE）→ git/快照回滚 → 默认延迟生效 → 高风险变更（增删 MCP）走权限通道 → 审计+自检 | B 综合 + GSimulator AgentConfigManager |
| Agent 自建/自改 skills | learning loop：任务后沉淀 skill、渐进披露、allowed-tools 并入权限 | Hermes + Skills 规范 |
| 自升级禁令 | Agent 可管配置/skills/子 Agent，但不能替换自身二进制 | 自毁风险 |
| 状态查询=最低权限 | /health、agent 状态、事件查询全部 guest 可读 | iBotMosire H8 |

### 7.7 事件存储与个人信息模型（自研核心）
| 注意点 | 说明 | 依据 |
|---|---|---|
| append-only 事件日志 + 快照 + 检索 | 事件即状态（event-sourced）；每事件一个不可变记录；定期快照；FTS 检索 | OpenHands EventLog + Hermes FTS5 |
| 实体模型最小起步 | 第一版只做 Task/Conversation/Document/Claim/Evidence/Persona/World；学 GSimulator 的分层（World/Node/Checkpoint/Element）+ @ 引用 | GSimulator 实践 |
| schema 版本化 + 迁移工具 | 长期资产，演进必须可迁移可修复 | Hermes state_schema/repair |
| 事件词汇表对齐 AG-UI | tool_started/tool_done/llm_delta/run_stage 等已是 AG-UI 雏形，正式对齐 | GSimulator GSimEvent |
| 存储选型以 C 子调查为准 | SQLite（FTS5）为基线候选 | （待 C 收稿定稿） |

### 7.8 安全
| 注意点 | 说明 | 依据 |
|---|---|---|
| 沙箱三档 | ReadOnly / WorkspaceWrite / DangerFullAccess + 不可恢复黑名单常开 | Codex |
| Java 无 SecurityManager | 子 Agent 沙箱=进程级（stdio 子进程 + OS 级 bwrap/容器）——这是硬约束 | JEP 411 + C |
| Prompt injection 当常态 | 工具输出一律不可信；高危工具白名单+参数范围+干跑预览；FIDES 式信息流标签思想可借鉴 | B（MAF ADR-0024） |
| 网络面默认 127.0.0.1 | 对外开口需独立授权与限流 | iBotMosire |
