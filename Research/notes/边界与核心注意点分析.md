# 边界与核心注意点分析（主笔工作文件，最终并入调查报告.md）

> 本文件是我（主 agent）基于一手核实（repos 抽查 + iBotMosire/GSimulator 文档亲读）形成的分析结论。
> 写作时间 2026-09-08。子调查 A-D 的笔记到位后，将与本文件合并成最终调查报告。

## 1. 目标软件的一句话定义（需求转写）

> 一个 Java 21、Maven 多模块、依赖最小化的 **Agent 运行时**：以一个大 Agent（Brain）为核心，可自由创建/销毁**多个权限各异的子 Agent**；对外用 **MCP**（工具/数据）、**A2A**（Agent 间互操作）、**AG-UI**（用户界面）说话；对内用**统一事件存储 + 个人信息模型 + 权限身份**把一切状态管起来；并且**运行时自身（配置、模块、skills、子 Agent）可被 Agent 管理**。

三个空目录的最自然映射（仅推测，供后续确认）：
- `AgentLibMosire` = Agent 公共库（协议适配、工具注册、权限、事件、模型路由）；
- `BrainMosire` = 大 Agent（推理循环、上下文构造、子 Agent 编排）；
- `MainMosire` = 主程序/网关（组装、AG-UI/A2A/MCP 入口、进程管理、CLI/守护）。

## 2. 与既有实践（iBotMosire/GSimulator）的延续与差异

延续（直接复用设计语言）：
- `AgentTool` 唯一工具接口 + `ToolRegistry` 动态注册 + MCP 只是协议适配层。
- 权限三要素 `requiredLevel` / `sensitive` / `destructive` + Bearer token 三级（guest/default/system）、逐请求校验、拒绝即终局、无审批流。
- 进程级隔离做安全边界（QQWS 独立进程的经验 → 子 Agent 天然应是子进程）。
- 纯 JDK 路线：Java 21 + 虚拟线程、jdk.httpserver、Jackson、SLF4J+Log4j2、shade 单 jar、不上 Spring。
- MCP 协议层 `hand-rolled | sdk` 可切换模式（iBotMosire §6.1）——**新项目直接继承这个开关**。

差异（新项目必须新增的能力）：
- 从"单槽位外部 Agent（claude-code/opencode）"→"**自研 Brain + N 个子 Agent**"：需要 AgentRegistry、子 Agent 模板、运行时生命周期、每 Agent 权限集（而不仅是每 token 权限级）。
- 从"QQ 网关"→"通用 Agent 运行时"：需要 AG-UI（用户界面）、A2A（与其他 Agent 互操作）。
- 从"Agent 自管上下文"→"**统一事件存储 + 记忆/上下文构造**"：GSimulator 的 EventBus/GSimEvent 只是雏形，缺持久化与检索。
- 从"手写 JSON-RPC MCP(2024-11-05)"→"官方 SDK（Tier 2, 2.0.x 追 2025-11-25）+ 2026-07-28 新规范形态"。
- 自管理闭环：Agent 可修改自身配置/skills/模块（iBotMosire 尚未做，Hermes 的 learning loop 是参照）。

## 3. 核心注意点清单（报告的"骨架结论"，逐条展开进最终报告）

### 3.1 协议层
1. **MCP**：官方 Java SDK = `io.modelcontextprotocol.sdk`，**Tier 2**（非 Tier 1），2.0.x 稳定线追踪 **2025-11-25** 规范；**2026-07-28 规范（stateless core/MRTR/header 路由）在 3.x，首个 milestone 计划 2026-09**。→ 起步锁 2.0.x；协议形态按 2026-07-28 设计（无会话、`server/discover`、`subscriptions/listen`）；保留 iBotMosire 的 hand-rolled/sdk 开关。**注意**：2026-07-28 弃用 Roots/Sampling/Logging 与 legacy HTTP+SSE，新代码不得依赖。
2. **A2A**：v1.0 stable（原始资料称 2026-03-12 发布，子调查 A 将核实）；官方 `org.a2aproject.sdk` Java SDK（Apache-2.0，JSON-RPC/gRPC/REST 三 transport，client+server，有 TCK）。→ 子 Agent 对外互操作首选；**轻量化取舍：先 JSON-RPC transport，gRPC 需另引依赖可后置**。
3. **AG-UI**：规范成熟（python/typescript/dotnet 官方 SDK）；**Java SDK 在 community 目录**（Apache-2.0、零依赖 core、Flow.Publisher 流、JDK HttpClient client）——可用，但要接受"社区维护"风险，并准备"手写 SSE/WebSocket 事件映射"的 fallback（事件模型本身简单）。
4. **ACP**：当前稳定协议版本 1（schema v1/v2，线兼容看协商的 protocolVersion）；Java SDK `com.agentclientprotocol:acp-core:0.16.0`（0.x 尚非 1.0，annotation/sync/async、stdio+WebSocket）。→ 二期（让编辑器接我们的 coding 能力 / 我们接外部 coding agent）。
5. **Agent Skills**：规范要点已核实（name/description 约束、allowed-tools experimental、<5000 tokens 渐进披露、scripts/references/assets）。用户已有实践（TanwenResearch skills/tanweng-persona 完全符合形态）。→ 直接实现"技能目录 + 渐进加载 + allowed-tools 并入权限"。
6. **AGENTS.md**：用户已有实践（GSimulator/AGENTS.md 质量很高）。→ 新项目自己也要写；同时实现"项目上下文注入器"。
7. 观察不动手：ANP/UCP/AP2/A2UI(候选)/MCP Apps(可留给 UI 二期)。

### 3.2 子 Agent 模型（本软件的灵魂）
- **定义方式**：模板化（id + system prompt + skill 集 + 工具权限集 + 模型路由 + 配额）+ 运行时实例（进程）。参考 Hermes isolated subagents、MetaGPT 角色 SOP、OpenHands agent 配置。
- **权限**：在 iBotMosire 三要素基础上加**每 Agent 权限集**维度：`grantedTools[]`（白名单）、`deniedTools[]`、`toolParams 白名单`（如仅某 QQ 号、仅某 worldId）、`scope`（只能看某项目/某世界的数据）。A2A/MCP 里子 Agent 拿**独立的、最小权限的 token/身份**，而不是共享 system token。**GSimulator 的 ToolCategoryRegistry + CliToolPermissionGate 是现成起点**。
- **隔离**：Java 无 SecurityManager（已移除）→ **子 Agent = 子进程**（stdio MCP 子进程是最干净形态；也天然支持"子 Agent 是外部程序如 claude-code/codex"——iBotMosire 已验证此路）。进程内"逻辑隔离"仅用于低风险工具。
- **生命周期**：spawn / pause / resume / kill / list / inspect（events 全记录）；崩溃恢复（状态在 Event Store，重启可续）。
- **防跑飞**：沿用 iBotMosire 硬顶（maxTurns/maxToolCallsPerTurn/timeBudget）+ 配额记账（token 消耗、费用）→ 超限即 kill 并记录。

### 3.3 大 Agent（Brain）
- 推理循环（ReAct 式 tool-use loop）是自研部分——协议不管这个。
- 上下文构造：会话历史 + 相关记忆检索 + 相关 skills 元数据 + AGENTS.md/项目上下文 + 工具目录（分页/过滤后）+ 配额预算剩余提示。
- 上下文压缩：Hermes micro-compaction、Codex 的自动压缩思想 → 事件日志是压缩的输入。
- 模型路由：多 provider（OpenAI 兼容 REST + Anthropic 兼容 + 国内 GLM/DeepSeek 等）；每任务/每子 Agent 可配不同模型（iBotMosire adapters 已示范 SiliconFlow GLM-5.2）。轻量做法：**HttpClient + SSE 手解流**，不引各家 SDK（子调查 C 将给出结论）。

### 3.4 自管理闭环（本软件区别于现有一切的关键）
- **配置即数据**：全部配置（agent 模板、tools 白名单、模型、skills 索引）是 Event Store 可读写的 JSON 文档，带 schema。
- **Agent 可改自身**：改配置走"提案 → 校验（JSON Schema + 语义校验）→ 原子写 → 生效/回滚 → 记事件"闭环；危险项（如把自己权限扩大）需要**权限单调性规则**（一个 agent 不能授予自己/子 Agent 超过自身的权限——capability 单调递减）。
- **Agent 可扩展自身**：skills 自创建/自改进（Hermes learning loop 的 Java 版）；新工具以"外部 MCP server 子进程"方式挂载（工具即配置：command + env + args，MCP stdio client 拉起）。
- **Agent 可管理子 Agent**：spawn/kill 本身是 system 级工具 → Brain 可编排；但**不允许自升级二进制**（升级走外部流程，避免自毁）。
- **运行时可观测**：所有状态查询（agent/工具/事件）是 guest 工具——iBotMosire H8 原则。

### 3.5 事件存储与个人信息模型（自研核心，协议不管的部分）
- append-only 事件日志（conversation/tool_call/observation/decision/config_change/agent_lifecycle…）+ 定期快照 + 索引检索（SQLite FTS5 或等价物，参照 Hermes FTS5+LLM 摘要）。
- 实体模型：Person/Project/Conversation/Game/Entity/Event/Claim/Evidence/Thought/Decision/Task/Intent/Relationship/Document/Session/WorldState —— 第一版只做最小集（Task/Conversation/Document/Claim/Evidence/Persona/World），学 GSimulator 的 World/Node/Checkpoint/Element 分层与 `@` 引用。
- **注意**：这是长期核心资产，数据结构演进要可迁移（schema 版本化 + 迁移工具，参照 hermes_state_schema/repair 的经验）。

### 3.6 轻量化（贯穿一切）
- 依赖最小：Jackson + 官方 MCP/A2A/ACP SDK + （可选）vertx/undertow 作网关；**禁 Spring**（延续既有路线）。
- 启动：JVM + AppCDS；GraalVM native 仅作远期选项（Jackson/Netty 反射成本需评估，子调查 C 核实）。
- 发行：shade 单 jar / jlink；模块懒加载（MCP server 按需拉起，不用不占内存）。
- **性能边界意识**：大 Agent 单会话上下文几万 token 的构造/压缩是主要 CPU 点；虚拟线程覆盖 I/O 面。

### 3.7 安全
- 密钥管理：provider key 不进工具可读范围（除显式 system 白名单）；环境变量 + 权限门。
- Prompt injection：工具输出一律视为不可信数据（子调查 B 会总结各项目做法）；高危工具（shell/文件写/消息发）白名单 + 参数校验 + 干跑预览。
- 网络面：MCP/A2A/AG-UI 默认绑 127.0.0.1；对外暴露需独立授权。
- 审计：所有工具调用/配置变更全量事件化（Event Store 天然审计）。

### 3.8 工程与测试
- 确定性测试：Mock 模型（固定响应）、假子进程（iBotMosire 假 claude 模式）、事件重放测试。
- 协议合规：MCP conformance tests、A2A TCK 可接入 CI。
- 可观测性：结构化日志 + Prometheus 预留（iBotMosire §13）；OpenTelemetry 二期（子调查 C 核实 Java 现状）。

### 3.9 许可证与合规
- 采用的 SDK 全部宽松许可：MCP Java SDK MIT、a2a-java Apache-2.0、ACP Java SDK（许可待核实）、AG-UI community Apache-2.0 → 商用/闭源无碍。
- Dify/Open WebUI 许可证带附加条件：**只借鉴设计，不抄代码**。
- Agent 生态数字（stars/MAU）无法完全核实，报告中如实标注。
