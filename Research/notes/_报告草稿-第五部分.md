## 四、参考架构：12 个项目告诉我们什么

### 4.0 总体判断

- **主循环选型**：自由 tool-calling 循环（OpenCode/Codex/Goose/Hermes/Letta）是个人 Agent runtime 的事实标准；**推荐 = tool-calling 循环 + 事件流记录**（OpenHands 的 event-sourced 思想）。工作流 DAG（n8n/Dify）与 SOP 流水线（MetaGPT）适合作为"子 Agent 任务的实现载体"，不适合做主循环。
- **子 Agent 最成熟范式**：OpenCode 的"agent 模板（数据不是代码）+ permission 映射（allow/ask/deny）+ child session 树 + 只读子 agent"——几乎就是"自由创建不同权限子 Agent"的现成答案。
- **自管理有先例且可行**：Letta V2 把"agent 改写自身记忆/技能/提示词"当卖点（MemFS 用 git 管上下文，天然可回滚）；安全闭环 = schema 校验 + 原子写 + 版本化回滚 + 高风险变更走权限请求 + 审计。

### 4.1 五个重点项目的"抄什么"

**OpenCode（MIT，借鉴优先级最高）**
- client/server 拆分：core 是 headless HTTP server（127.0.0.1:4096，OpenAPI 3.1 发布 `/doc`，SDK 由 spec 生成），TUI/Web/Desktop/IDE 都是纯客户端；
- 事件流 = `GET /event` SSE 总线；**权限请求是普通 HTTP 交互**（`POST /session/:id/permissions/:permissionID` 回 `{response, remember?}`），remember 是"逐次询问 ↔ 自动批准"的连续谱；
- agent 模板：JSON（带 $schema）或 Markdown frontmatter，字段 description/mode/prompt/model/permission/steps；内置 primary（build 全权、plan 只读）与 subagent（explore/scout 只读）；
- 上下文管理：compaction/title/summary 做成**隐藏系统 agent**（hidden: true，自动触发）；
- 动态 MCP：`POST /mcp {name, config}` 运行时增删。

**Hermes Agent（MIT）**
- 窄腰铁律："core is a narrow waist; capability lives at the edges"——新能力不进 core，走 MCP/插件/skills；
- **prompt-cache 不变量**：历史上下文只在压缩时可变，配置修改默认"延迟生效（下次会话）+ 显式 --now"——"自管理"与"成本"耦合的关键教训；
- 子 Agent：`SubagentLaunchRequest`（goal/context/role/model/allowed_toolsets/blocked_tools/working_directory/timeout）+ 完整状态机（PENDING→RUNNING→SUCCEEDED/FAILED/CANCELLED…）+ depth 限深 + 硬禁 delegate（防递归）；隔离 = 七种 terminal backend（local/Docker/SSH/…/Vercel Sandbox）可切换；
- 权限：approvals.mode=smart/manual/off + UNRECOVERABLE_BLOCKLIST 常开（rm -rf /、fork bomb）+ 凭据目录写硬阻断 + 超时 fail-closed；
- 学习闭环：从经验自建 skills、FTS5 全文检索 + LLM 摘要跨会话召回、micro-compaction。

**Codex CLI（Apache-2.0）**
- **sandbox_mode 三档：ReadOnly / WorkspaceWrite / DangerFullAccess**——三分法可直接搬；
- OS 沙箱是独立 crate 群：bwrap（bundled bubblewrap）/ linux-sandbox / windows-sandbox / **execpolicy**（策略与沙箱实现分层）——Java 对应物 = 进程隔离 + OS 级 bwrap/seccomp + 我们的 ToolPermissionGate；
- 上下文硬约束（其 AGENTS.md）：不重写历史、注入项有界有硬上限、单条 >10k token 不允许；压缩可用独立模型（compact_model_fallback）。

**Letta / letta-code（Apache-2.0 + 品牌排除）**
- **memory-first**：三层记忆（热 = persona/human 写入式块随对话被 agent 编辑；温 = 会话检索；冷 = 外部存储按需 recall）；
- **MemFS**：记忆即文件、文件进 git（可推 GitHub）——自修改天然可 diff/revert/审计；
- **自配置设计**：agent 改写自身记忆/技能/提示词，甚至通过 mods（全信任进程内代码）改写 harness；`/doctor` 审计记忆质量；
- 子 Agent = 子进程 + tools 白名单 + memoryBlocks 限制 + 记忆守卫（即使 unrestricted 也不碰其他 agent 记忆目录）。

**Goose（Apache-2.0）**
- 三组件模型：Interface（桌面/CLI）— Agent（交互循环）— **Extensions（即 MCP 服务器）**——MCP-first 扩展；
- 内部子代理 = 独立 goose 实例（禁再派生/禁管扩展/禁管调度 + 自然语言收缩权限）；**外部子代理 = 任意 MCP 服务器注册为 subagent**（官方示例把 Codex CLI 作为 stdio MCP subagent + 其自带沙箱做隔离——用别人的沙箱做自己的隔离）；
- 教训：默认"完全自主"模式偏激进，我们的默认策略应保守。

### 4.2 综合结论：七个设计决策的"参考答案"

1. **子 Agent 定义**：模板化（JSON Schema 校验的配置文件/带 frontmatter 的 Markdown）+ 目录扫描加载；字段含 description（供主 Agent 路由）/prompt/model/tools 白名单/permission 映射/steps/超时。数据不是代码 → 可被 Agent 自管理（GSimulator agents/*.json 已是同构实践）。
2. **权限收缩（强度递增四档）**：permission 映射（allow/ask/deny）→ 工具白名单 → 只读 agent → **隔离升级（同进程线程 → 子进程 → OS 沙箱）**。默认不需要进程级隔离，但必须预留 Executor 抽象（本地/子进程/容器可切换）。**权限传递单向：默认继承父级、可逐项收紧为 deny，子 Agent 不能给自己提权。**
3. **上下文管理**：隐藏 compaction agent（OpenCode）+ prompt-cache 不变量（Hermes）+ 写入式记忆块（Letta）+ FTS 检索召回（Hermes FTS5，JVM 有成熟 SQLite 绑定）——语言无关设计，直接照搬。
4. **事件与 UI 解耦**：headless server + OpenAPI + SSE 总线 + 权限请求 HTTP 端点（OpenCode 模式）；最小事件集 = session.* / message.* / tool_call.* / permission.request|response / state.snapshot / error / heartbeat；再映射到 AG-UI（P1）。SSE 单向流 + REST 写，比全双工 WS 简单。
5. **自管理闭环六要素**：分层配置合并 → JSON Schema 校验 → 原子写 + git 版控回滚 → 默认延迟生效（缓存友好）→ 高风险变更（增删 MCP=执行任意代码）走权限通道 → 审计 + 自检命令（/doctor）。我们的既有件：GSimulator AgentConfigManager（tmp+ATOMIC_MOVE+reload）+ iBotMosire 权限门。
6. **扩展机制**：MCP-first（Goose/Hermes 窄腰）——扩展即 MCP server 子进程，按需拉起、空闲即关；skills 为知识型能力；插件为最后手段（进程内代码需全信任，Letta mods 的教训）。
7. **轻量化**：单二进制/毫秒启动是 Rust/Bun 语言红利，Java 对应物 = jlink + AppCDS + CRaC + GraalVM（详第五章）；**真正的轻量思路 = 小 core + headless + 协议化扩展 + 前端可选**。

### 4.4 许可证要点（全部核实原文，2026-09-08）

- 可放心借鉴：Hermes MIT、OpenCode MIT、Codex Apache-2.0、Goose Apache-2.0、MetaGPT MIT、Browser Use MIT、OpenHands MIT、MAF MIT；Letta Apache-2.0 但**品牌资产被排除**（复用代码勿带其标识）。
- 只能抄设计：n8n（Sustainable Use License，限内部/非商业）、Dify（禁多租户运营、禁去 LOGO）、Open WebUI（品牌条款，演变史 MIT→BSD-3→品牌条款）。
- 我们采用的 SDK 同样宽松：MCP Java SDK MIT、a2a-java Apache-2.0、ACP Apache-2.0、AG-UI community Apache-2.0。

### 4.5 对"自研核心"的印证

12 个项目没有一个解决"个人数字世界的统一描述"（Person/Event/Claim/Decision/WorldState 关系模型 + 统一事件存储）——最接近的是 OpenHands 的 event-sourced 循环（事件即状态、append-only、可回放）与 GSimulator 的 World/Node/Checkpoint/Element + @ 引用。**这确认了自研边界：Personal Information Model + Event Store + Permission/Identity + Context Construction，其余全部用标准。**
