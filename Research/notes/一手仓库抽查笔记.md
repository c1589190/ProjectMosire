# 一手仓库抽查笔记（one-shot repo checks）

> 本笔记记录我在 Research/repos 中**亲手抽查**得到的事实（区别于子调查基于 Web 的结论）。抽查时间：2026-09-08。所有路径相对 /home/cna/ProjectMosire/Research/repos。

## 1. MCP Java SDK（repos/java-sdk，即 modelcontextprotocol/java-sdk）

- 仓库根 pom 版本：**2.1.0-SNAPSHOT**（主开发版本；Maven Central 上有正式 release，具体版本以 badge/Maven 为准）。
- 许可证：MIT。Java 17+。
- 模块：`mcp`（主聚合/发行）、`mcp-core`、`mcp-json-jackson2`、`mcp-json-jackson3`、`mcp-bom`、`mcp-test`、`conformance-tests`、`docs`。
- Maven 坐标（README badge）：`io.modelcontextprotocol.sdk:mcp`。
- 支持同步与异步两种通信模式（README 明言 synchronous and asynchronous）。
- README 提及 Spring AI 的 MCP 扩展（starters、annotations、OAuth/API-key 安全）——说明 Spring 生态在此 SDK 之上有额外封装；对我们（轻量化）而言**不必引入 Spring**。
- 仓库自带 AGENTS.md、DEPENDENCY_POLICY.md、VERSIONING.md——工程规范参考价值。

## 2. A2A Java SDK（repos/a2a-java，即 a2aproject/a2a-java）

- 许可证：Apache-2.0。Java 17+。
- 定位：帮 Java 应用以 A2A server 身份运行；**client 与 server 双角色**，覆盖 **JSON-RPC、gRPC、REST** 三种 transport。
- Maven 坐标（README Quick Start）：`org.a2aproject.sdk`（具体 artifact 如 jsonrpc 参考 server 见 README）。
- 模块概览：`client`、`server-common`、`http-client`、`transport`、`jsonrpc-common`、`spec-grpc`、`spec`、`common`、`itk`、`tck`、`boms`、`compat-0.3`、`integrations`、`examples`、`test-utils-docker`。
- 官方文档站：a2aproject.github.io/a2a-java（Server Guide / Client Guide / Javadoc / 社区文章）。
- 有 TCK（测试兼容套件）→ 实现合规性可测，这是重要优点。

## 3. ACP Java SDK（repos/acp-java-sdk，即 agentclientprotocol/java-sdk）

- README 标题：**ACP Java SDK**，"Pure Java implementation of the Agent Client Protocol for building both clients and agents"。
- 坐标：`com.agentclientprotocol:acp-core`，当前版本 **0.16.0**。
- 模块：`acp-core`、`acp-annotations`、`acp-agent-support`、`acp-websocket-jetty`、`acp-test`。
- 特性：Java 17+、类型安全、**stdio 与 WebSocket** transport、capability negotiation、结构化错误处理。
- 三种 agent 编写风格：**annotation-based**（`@AcpAgent`、`@Prompt`）、**sync**（普通返回值）、**async**（Project Reactor `Mono`）。
- 文档站：lab.pollack.ai/docs/acp-java-sdk。
- 注：WebSocket 实现基于 Jetty（acp-websocket-jetty）。

## 4. AG-UI Java SDK（repos/ag-ui，即 ag-ui-protocol/ag-ui）

- 位于 **`sdks/community/java`**——注意层级：官方一等 SDK 是 `sdks/python`、`sdks/typescript`、`sdks/dotnet`；Java 在 **community** 目录。
- 模块：`core`（协议类型、事件、Agent 抽象、可插拔 Serializer，**零第三方运行时依赖**，流类型用 JDK `java.util.concurrent.Flow.Publisher`）、`client`（`HttpAgent`，JDK HttpClient 解码 SSE 事件流）、`server`（把 Agent 暴露为 AG-UI 服务）。
- 许可证：Apache-2.0。Java 17+。Maven 3.8+。
- 包名示例：`com.agui.community.core.agent.Agent`。
- 仓库另有 `docs/sdk/java/{overview.mdx, core, client, server}`，说明官方文档站也收录 Java 用法。
- 结论：**AG-UI Java SDK 真实存在，但属社区维护**——可用、可 fork，但稳定性和跟进速度风险高于 MCP/A2A 官方 Java SDK。

## 4b. MCP Java SDK 版本线与规范跟进（补充，重要）

- Release lines（CHANGELOG.md）：**2.0.x（2.0.1, 2026-08-19）追踪 2025-11-25 规范**；1.1.x / 0.18.x 仅安全补丁。
- **2026-07-28 规范的支持在 3.x**（ROADMAP.md：实现 `server/discover`、SEP-2575 stateless lifecycle；**首个 3.0.0 milestone 计划 2026-09**）。
- 2.x 已出现部分 stateless 影子（docs/server.md 的 `McpStatelessSyncServer`、MIGRATION-2.0.md 提及）——stateless 能力在 2.x 部分存在，但完整新规范在 3.0。
- **落地含义**：现在起步应锁 2.0.x（稳定、追踪 2025-11-25）；stateless core/MRTR 等新特性等 3.0 再升级，或暂用 2.x 的 stateless 服务器形态做过渡。

## 4c. MCP 官方 SDK 分级（spec 仓库核实）

- `docs/docs/2026-07-28/sdk.mdx` 的官方 SDK 表：**Java SDK = Tier 2**（紫色 Badge 明确标注）。
- 2026-07-28 GA 博客列举的 Tier 1 为 **TypeScript / Python / Go / C#**；Rust SDK 为 beta；Java 不在 Tier 1 名单。
- 分级体系（docs/community/sdk-tiers.mdx）：Tier 1 = 100% conformance、发布前跟进新规范；Tier 2 = 80% conformance、新特性 **6 个月内**跟进、有稳定版本与文档。
- **修正原始资料**：用户材料说 Java SDK 是"正式 Tier SDK 路线"——准确表述应为：**官方 SDK（modelcontextprotocol 组织名下），Tier 2**，不是 Tier 1。可用，但跟进速度与规范领先度低于 TS/Py/Go/C#。

## 4d. MCP 规范 2026-07-28 GA（spec 仓库 blog 一手核实）

- 发布日期 2026-07-28，标题 "The 2026-07-28 Specification"。
- 确认特性：stateless protocol core（废除 initialize/initialized 与 Mcp-Session-Id，新增可选 `server/discover`）；**MRTR**（Multi Round-Trip Requests，取代 server→client 采样/elicitation 的双向常开流）；**header routing**（`Mcp-Method`/`Mcp-Name` 头，网关直接按头路由/授权）；**cacheable lists**（cache hints + 确定性排序）；**授权硬化**（RFC 9207 issuer 校验、DCR→CIMD 转向）；**正式 extensions framework**（Tasks 移入 `io.modelcontextprotocol/tasks` 扩展、`tasks/get`+`tasks/update`、`subscriptions/listen` 替代旧 GET 通知端点）；**12 个月最低弃用窗口**。
- **弃用清单**：Roots、Sampling、Logging 已弃用（新实现不要采用）；legacy HTTP+SSE transport 官方弃用（一年过渡）。
- 下载量：Tier 1 SDK 合计月下载近 5 亿，TS/Python 各自累计破 10 亿（与原始资料数字一致）。
- **落地含义**：我们新项目直接按新规范形态设计（无会话、按请求自描述），不要在新代码里依赖 Roots/Sampling/Logging 和旧 HTTP+SSE。

## 4e. ACP 规范本体（repos/agent-client-protocol）

- 主仓库是 Rust：`agent-client-protocol-schema` crate + JSON Schema artifacts（`schema/v1`、`schema/v2`，随 GitHub Release 发布，供 SDK 生成器消费）。

- 顶层 runtime crate 是 `agent-client-protocol`（Rust 侧 client/agent runtime）。
- 配套 Java SDK 见本笔记第 3 节（0.16.0）。

## 6. Hermes Agent（repos/hermes-agent）一手要点

- 许可证 MIT；主体是 **Python**（hermes_*.py 一长串状态管理文件）+ Bun/TS（web/tui 部分）。
- 定位："self-improving AI agent"：内置学习闭环——从经验创建 skills、使用中自我改进、周期 nudge 持久化知识、搜索自己历史会话（FTS5 + LLM 摘要）、跨会话用户建模（Honcho dialectic）；**兼容 agentskills.io 标准**。
- 状态管理是一整套独立文件：hermes_state_{wal,compression,schema,registry,repair,search,sessions,usage,fts,dbfile,...}.py → 有 WAL、压缩、FTS 检索、schema/registry、修复工具；还有 micro-compaction 文档（docs/micro-compaction.md）。
- 子 Agent：`agent/tools/delegate_tool_{config,dispatch,tasks}.py`——**isolated subagents** 并行委派；还有"写 Python 脚本经 RPC 调工具，把多步流水线折叠成零上下文成本回合"的机制。
- 终端后端七种：local、Docker、SSH、Singularity、Modal、Daytona、Vercel Sandbox → **隔离层是"终端/执行后端"抽象**，sandbox 是可替换执行环境。
- 单 gateway 进程聚合 Telegram/Discord/Slack/WhatsApp/Signal/CLI；内置 cron 调度器。
- 有 `acp_adapter/`（对接 ACP）、`plugins/`、`optional-mcps/`、`optional-skills/`、`toolsets.py`、`providers/`（模型路由）。
- docs 有 ADR.md、design/（multiplexing-gateway、profile-builder）、rfcs/、security/。
- **对目标软件的启示**：learning loop + 渐进式 skills + 状态 WAL/压缩/FTS + 可替换执行后端 + 单 gateway 多前端，全部是我们需要借鉴的"自管理"参照系。

## 10. Agent Skills 规范（repos/agentskills/docs/specification.mdx）一手要点

- 目录结构：必需 `SKILL.md`；可选 `scripts/`、`references/`、`assets/`。
- SKILL.md = YAML frontmatter + Markdown body。字段：`name`（必需，1-64 字符，小写字母/数字/连字符，须与目录名一致）、`description`（必需，1-1024 字符，须写"做什么+何时用"）、`license`、`compatibility`、`metadata`、`allowed-tools`（可选，空格分隔预批准工具，如 `Bash(git:*) Bash(jq:*) Read`，**标注 experimental**）。
- 渐进式披露：metadata 常驻 → 激活时加载 body（建议 < 5000 tokens）→ 细节放 references；主 SKILL.md 建议 < 500 行；文件引用一层深。
- 官方验证工具：skills-ref（validate / read-properties / to-prompt，输出 `<available_skills>` XML）。
- **落地含义**：`allowed-tools` 是 skill 级权限声明——我们的子 Agent 权限模型应能消费该字段；to-prompt 的 XML 形态可复用于"技能目录注入"。

## 17. 补充：a2a-java 的 CDI 依赖面（轻量化关键细节）

- **client/base 零 jakarta 依赖** → 我们作为 A2A client 调别的 Agent 是"纯 JDK 友好"的。
- **server-common 依赖 jakarta.enterprise.cdi-api + jakarta.inject-api**；参考 server（reference/jsonrpc、rest、grpc）是 CDI 风格（示例代码用 @ApplicationScoped/@Produces，README 的 Javadoc 链接为 1.3.0 Final）。
- 落地含义（两个选项，建议列入后续设计决策）：
  1. A2A server 走 SDK：接受 CDI（Weld/Quarkus）这一个端点上的重量，换取完整合规 + TCK 可测；
  2. 轻量路线：A2A server 端点手写最小 JSON-RPC（HTTP+JSON 绑定），复用 spec 类型/Agent Card 概念——与用户三代手写 MCP 的经验同构，但要注意"手搓协议"的历史教训，仅当 SDK 重量不可接受时选。
- 现状倾向：**先 SDK（client 用 client/base；server 用 reference-jsonrpc 风格 + 最小 CDI）**，因为 TCK 与 conformance 收益大；若 CDI 引入的启动/内存代价实测不可接受再回退选项 2。

## 19. 本机 Java 验证（2026-09-08，OpenJDK 21.0.12）

- 本机仅有 JDK 21（/usr/lib/jvm/java-21-openjdk-amd64），无更高版本。
- **虚拟线程可用**：`Executors.newVirtualThreadPerTaskExecutor()` 实测返回 isVirtual=true。
- **StructuredTaskScope（结构化并发）在 21 是 preview**：实测 `--enable-preview` 下 ShutdownOnFailure + fork/join 正常（ScopedValue 同为 preview 系）。
- **SecurityManager 已死**：`System.getSecurityManager()` 编译警告 "deprecated and marked for removal"，运行时返回 null（JEP 411 弃用 → JDK 24 JEP 486 永久禁用）。→ 进程内沙箱在 Java 上不可行，子 Agent 隔离必须进程级/OS 级。
- 落地含义：主循环与工具执行可放心用虚拟线程（I/O 面）；结构化并发仅在能接受 preview 开关时用（否则用 ExecutorService + try-with-resources 模式）；沙箱依赖 OS（bwrap/容器/目录 jail）。
