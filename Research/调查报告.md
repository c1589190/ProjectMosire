## 摘要（一页结论）

1. **协议全有现成标准，Java 全有路可走，一个都不该自造**：MCP（官方 Java SDK 2.0.1，注意是 **Tier 2** 非 Tier 1）、A2A（官方 Java SDK 1.3.1.Final，三传输 client+server，v1.0 已稳定）、AG-UI（Java SDK 存在但**社区级 0.1.0**，需薄适配层+手写兜底）、ACP（官方纯 Java SDK 0.17.0，二期）、Agent Skills 与 AGENTS.md（纯文件格式，零 SDK 成本）。P0 = MCP + A2A + Skills + AGENTS.md。
2. **自研边界被再次印证**：没有任何协议/产品解决"个人数字世界的统一描述"——Personal Information Model + 统一事件存储 + 权限/身份 + 上下文构造，才是真正要自己做的核心。
3. **子 Agent 范式有现成答案**：OpenCode 的"agent 模板（数据不是代码）+ permission 映射（allow/ask/deny）+ child session 树 + 只读 agent"几乎就是"自由创建不同权限子 Agent"的成品设计；Hermes 的 `SubagentLaunchRequest`（goal/allowed_toolsets/blocked_tools/timeout/depth）是可照抄的 spawn API。
4. **Java 沙箱的硬约束**：SecurityManager 已死（JDK 24 起永久禁用）→ **信任边界 = 进程边界**；"子 Agent = stdio 子进程 + 网关工具白名单 +（可选）bwrap"是 Java 下最现实也最轻的沙箱，与 MCP stdio 天然同构。
5. **自管理是可行且被头部项目验证过的**：Letta（MemFS git 版控记忆 + 自配置设计）、n8n/Open WebUI（API 自举）、Hermes（learning loop 自建 skills）都在做。安全闭环 = schema 校验 + 原子写 + 回滚 + 高风险变更走权限通道 + 审计；**权限单调性**（Agent 不能给自己提权）与**自升级禁令**是两条红线。
6. **轻量化的 Java 姿势**：核心 = 六个依赖坐标（mcp-core + jackson + slf4j + json-schema-validator + sqlite-jdbc）就能跑起来；主脑 JVM 常驻（shade 单 jar + AppCDS + 可选 jlink 52MB 运行时），子 Agent/工具用原生进程；GraalVM 因 closed-world 与协议 SDK 不兼容，**不首选**。
7. **你手里的底子比想象中厚**：GSimulator（ToolLoop/权限 Guard/子 Agent 配置 CRUD 自管理/事件总线）与 iBotMosire（2026-07-28 MCP 设计/三级 token 权限/进程隔离/防跑飞）合起来已是一个"主 Agent + 权限化子 Agent + 手写 MCP"的原型集群；新项目 = 剥离业务耦合 + 官方 SDK 替换手写协议 + 补 A2A/AG-UI/ACP 与进程沙箱。

## 二、需求转写与目标边界

### 2.1 目标软件一句话定义
> 一个 **Java 21、Maven 多模块、依赖最小化**的 Agent 运行时：以一个大 Agent（"大脑"）为核心，可**自由创建/销毁多个权限各异的子 Agent**；对外用 **MCP**（工具/数据）、**A2A**（Agent 间互操作）、**AG-UI**（用户界面）说话；对内用**统一事件存储 + 个人信息模型 + 权限/身份**把一切状态管起来；并且**运行时自身（配置、模块、skills、子 Agent）可被运行中的 Agent 管理**。

### 2.2 需求拆解（每个词对应一个"注意面"）

| 需求词 | 转写 | 对应章节 |
|---|---|---|
| Java | 延续 Java 21 + Maven 工程习惯 | 五（技术栈）、六（既有实践） |
| 多代码模块 | Maven 多模块、单向依赖、模块化扩展 | 七.1 |
| 兼容通用协议 | MCP/A2A/AG-UI/ACP/Skills/AGENTS.md | 三（协议栈） |
| 自由创建子 Agent | 子 Agent 模板 + 运行时注册表 + 生命周期 API | 七.3 |
| 权限不同 | 每 Agent 权限集（工具白名单/参数范围/独立凭证） | 七.5 |
| 能干的大 Agent | 自研推理循环 + 上下文构造 + 模型路由 | 七.4 |
| 一切可被 Agent 管理 | 配置即数据 + 自管理工具 + 权限单调性约束 | 七.6 |
| 轻量化 | 依赖最小化、启动快、内存省、能力按需拉起 | 七.9 |

### 2.3 边界判断：什么必须自研、什么绝不自研
- **绝不自研**：MCP（官方 Java SDK）、A2A（官方 Java SDK）、AG-UI（社区 SDK/手写兜底）、ACP（官方 SDK，二期）、Agent Skills / AGENTS.md（文件格式）。普通互联网协议（HTTP/JSON/JSON-RPC/SSE/OAuth/OIDC/OpenAPI/OTel/CloudEvents）同样不造轮子。
- **必须自研**（没有任何主流协议/软件替你解决）：**个人信息模型**（Person/Project/Conversation/Entity/Event/Observation/Claim/Evidence/Thought/Decision/Task/Intent/Relationship/Document/Session/WorldState 的实体关系）、**统一事件存储**（append-only 事件日志 + 快照 + 检索）、**权限与身份**（每 Agent 最小权限集、凭证发放、审计）、**上下文构造**（历史 + 记忆检索 + skills 目录 + 项目上下文 + 工具目录的组装与压缩）。

### 2.4 三个空目录的最自然映射（推测，待确认）
- `AgentLibMosire`：Agent 公共库（协议适配、工具注册与 Guard、权限模型、事件总线、模型路由、子 Agent 模板）；
- `BrainMosire`：大 Agent（推理循环、上下文构造、子 Agent 编排、记忆）；
- `MainMosire`：主程序/网关（进程组装、协议入口、配置加载、健康检查、发行）。

### 3.1 MCP（第一优先级）
- **规范**：2026-07-28 GA——stateless core（废除 initialize 握手与 Session-Id，每请求 `_meta` 自带版本/能力）、`server/discover`、MRTR（`resultType: input_required` 取代服务端反向请求）、`Mcp-Method`/`Mcp-Name` 头路由、可缓存列表（ttlMs/cacheScope/确定性排序）、授权硬化（RFC 9207 iss、DCR→CIMD）、正式 extensions 框架（Tasks 移入 `io.modelcontextprotocol/tasks`）、`subscriptions/listen` 取代旧通知端点。**弃用（新代码禁用）**：Roots、Sampling、Logging、legacy HTTP+SSE；12 个月最低弃用窗口。
- **Java SDK**：`io.modelcontextprotocol.sdk`，v2.0.1（2026-08-19），模块 mcp-core（无 JSON 绑定）/mcp-json-jackson2/jackson3/mcp-bom；stdio + Streamable HTTP + stateless transport client/server 齐全；API：`McpServer.sync/async(transport).build()` + `addTool`。Conformance server 40/40、client 9/10。**重要修正：官方定位是 Tier 2**（Tier 1 = TS/Python/C#/Go/Rust），新特性有约 6 个月滞后；2.x 追踪 2025-11-25，**2026-07-28 全量支持在 3.x（首个 milestone 计划 2026-09）**。
- **落点**：Brain 作为 MCP **client** 调外部工具；自身模块能力包装为 MCP **server**。起步锁 2.0.1，协议形态按 2026-07-28 设计（iBotMosire 已按此设计手搓层）；保留 iBotMosire 的 `mcp.mode = hand-rolled | sdk` 开关兜底；SDK 3.0 发布后升级并复用官方 stateless 传输。

### 3.2 A2A（第一优先级，子 Agent 互操作的标准答案）
- **规范**：v1.0.0 于 **2026-03-12** 发布（现 v1.0.1，2026-05-28）；172 家组织；2026-08-27 入 LF AAIF。本体 = `a2a.proto`（ProtoJSON）+ JSON/REST 绑定。Agent Card 必填 name/description/version/capabilities/defaultInputModes/defaultOutputModes/skills/supportedInterfaces，可选 signatures（JWS 签名卡）；TaskState 9 态；artifacts（Text/File/DataPart）；push notification（webhook 订阅）。
- **Java SDK**：`org.a2aproject.sdk`，**1.3.1.Final**（2026-09-03），Apache-2.0；client（零 jakarta 依赖）+ server-common + transport{jsonrpc,grpc,rest} 三传输 client+server，附 TCK。**注意：server-common 依赖 CDI（jakarta.enterprise/inject），参考实现绑 Quarkus**——决策点：接受 CDI 换完整合规+TCK，或（重量不可接受时）手写最小 JSON-RPC HTTP 绑定。
- **落点**：主 Agent 对外 = A2A **server**；调子 Agent/外部 Agent = A2A **client**；先 JSON-RPC transport。"子 Agent 可以是远程 A2A peer"——同一抽象覆盖进程内与跨进程/跨机器。

### 3.3 AG-UI（用户界面出口，P1）
- **规范**：**1.0 仍 Draft**；事件 8 族（Lifecycle/TextMessages/ToolCalls/Reasoning/State/Activity/**Subagents**/Passthrough）；**标准传输只有 HTTP+SSE（必）与 HTTP+Protobuf（可选），WebSocket 仅为自定义传输**（对原始资料的修正）；MetaEvents 已并入 Metadata。
- **Java 支持**：存在但社区级——`sdks/community/java`（core 零依赖、Flow.Publisher 流、client 用 JDK HttpClient），Central 坐标 `com.ag-ui.community:java-core/java-client/java-server` 0.1.0；一等 SDK 只有 TS/Python/.NET。
- **落点**：我们做 **server**。风险高（Draft + 0.1.0 + 社区）→ 隔离在薄适配层；**手写兜底最小事件子集**：RUN_STARTED → TEXT_MESSAGE_START/CONTENT*/END →（可选 TOOL_CALL_*、STATE_*）→ RUN_FINISHED + RunAgentInput + RUN_ERROR，SSE 直出。Subagents 事件族与子 Agent 树天然对齐（UI 原生展示归属/并行/终止）。

### 3.4 ACP（P2 可选）
- v1 = Latest（Zed + JetBrains），v2 Draft；本地 stdio JSON-RPC 必支持，远程 HTTP/WebSocket 官方标注 WIP；权限方法 = **`session/request_permission`**；plan 走 session/update 的 Plan 条目。
- 官方纯 Java SDK `com.agentclientprotocol:acp-core` **0.17.0**（annotation/sync/async 三风格、stdio+WebSocket-Jetty）。仅当面向编辑器场景时启用 agent 角色。

### 3.5 Agent Skills 与 AGENTS.md（P0 基础能力）
- **Skills**：SKILL.md frontmatter（name 必填且须与目录名一致、description 1-1024 字符；可选 license/compatibility/metadata/**allowed-tools**[实验]）+ scripts/references/assets；渐进披露三档（catalog ~50-100 token/技能 → 激活载正文 <5000 token → 资源按需）。无 SDK，自实现目录扫描 + YAML 解析 + 三档加载。**allowed-tools（如 `Bash(git:*) Bash(jq:*) Read`）直接映射为子 Agent 权限**。
- **AGENTS.md**：纯 Markdown、无必填字段、支持嵌套、最近文件优先。落点：每个模块仓库提供 AGENTS.md；操作第三方仓库时优先读取遵守。
- 用户已有合规实践：TanwenResearch `skills/tanweng-persona/`（frontmatter + references 渐进披露 + scripts 校验 + 伦理边界）、GSimulator `AGENTS.md`（连接/概念/命名空间/分页/@ 引用）——直接沿用。

### 3.6 MCP Apps / A2UI（P2）
- **MCP Apps**：2026-01-26 成为第一个正式 MCP 扩展且 production-ready；机制 = 工具 `_meta.ui.resourceUri` 声明 `ui://` 资源 → 宿主沙箱 iframe → JSON-RPC over postMessage 双向通信；宿主矩阵覆盖 Claude/VS Code/Goose/ChatGPT 等；无官方 Java 库，但 server 侧只需在 MCP 工具元数据手工加 `_meta.ui` + ui:// 资源端点——适合给工具配交互面板（如 Minecraft 控制台、地图）。
- **A2UI**：v0.9.1 生产 / v1.0 Candidate；消息 createSurface/updateComponents/updateDataModel/deleteSurface；纯 JSON 生成。观察 v1.0 定稿。

### 3.7 不碰与参考
- **ANP**：1.1 版、早期、采纳少——观察不绑定。**老 IBM ACP**：禁用。**AutoGen**：maintenance mode；后继 **Microsoft Agent Framework**（MIT，.NET/Python/Go，A2A/MCP 原生，无 Java）——仅参考其编排/skills/安全 ADR（FIDES 信息流标签、CodeAct 沙箱、用户批准内容类型）。

## 四、参考架构：12 个项目告诉我们什么

### 4.0 总体判断
- **主循环选型**：自由 tool-calling 循环（OpenCode/Codex/Goose/Hermes）是个人 Agent runtime 事实标准；**推荐 = tool-calling 循环 + 事件流记录**（OpenHands event-sourced 思想）。工作流 DAG（n8n/Dify）与 SOP 流水线（MetaGPT）只作子任务载体。
- **子 Agent 最成熟范式**：OpenCode 的"agent 模板（数据不是代码）+ permission 映射 + child session 树 + 只读子 agent"。
- **自管理有先例且可行**：Letta V2 把"agent 改写自身记忆/技能/提示词"当卖点（MemFS git 版控天然可回滚）。

### 4.1 五个重点项目的"抄什么"

**OpenCode（MIT，借鉴优先级最高）**：headless server（OpenAPI 3.1 发布 `/doc`）+ `GET /event` SSE 总线 + **权限请求是普通 HTTP 交互**（`POST /session/:id/permissions/:permissionID` 回 `{response, remember?}`，remember 是"逐次询问↔自动批准"的连续谱）+ agent 模板（JSON/Markdown，字段 description/mode/prompt/model/permission/steps）+ **隐藏系统 agent 做 compaction/title/summary** + 动态 MCP（`POST /mcp` 运行时增删）。

**Hermes Agent（MIT）**：窄腰铁律（"core is a narrow waist; capability lives at the edges"）+ **prompt-cache 不变量**（历史只在压缩时可变，配置修改默认延迟生效 + --now）+ 子 Agent 生命周期模型（`SubagentLaunchRequest`: goal/role/allowed_toolsets/blocked_tools/working_directory/timeout + 状态机 + depth 限深 + 硬禁 delegate）+ UNRECOVERABLE_BLOCKLIST 常开 + 凭据目录写硬阻断 + learning loop（经验自建 skills、FTS5+LLM 摘要跨会话召回、micro-compaction）。

**Codex CLI（Apache-2.0）**：**sandbox_mode 三档 ReadOnly/WorkspaceWrite/DangerFullAccess** + OS 沙箱独立 crate 群（bwrap/linux-sandbox/execpolicy——策略与实现分层）+ 上下文硬约束（不重写历史、注入项有界、单条 >10k token 不允许、压缩可用独立模型）。

**Letta / letta-code（Apache-2.0 + 品牌资产排除）**：memory-first 三层记忆（热=persona/human 写入式块、温=会话检索、冷=按需 recall）+ **MemFS（记忆即文件、文件进 git）** + 自配置设计（agent 改写自身记忆/技能/提示词）+ 子 Agent=子进程 + tools 白名单 + memoryBlocks 限制 + 记忆守卫。

**Goose（Apache-2.0）**：Interface—Agent—**Extensions（即 MCP 服务器）** 三组件 + 内部子代理=独立实例（禁再派生/禁管扩展）+ **外部子代理=任意 MCP 服务器注册为 subagent**（官方示例：Codex CLI 作为 stdio MCP subagent，用其自带沙箱做隔离）+ 教训：默认"完全自主"偏激进，我们的默认应保守。

### 4.2 七个设计决策的"参考答案"
1. **子 Agent 定义**：模板化（JSON Schema 校验配置/带 frontmatter 的 Markdown）+ 目录扫描；字段 description（供路由）/prompt/model/tools 白名单/permission 映射/steps/超时。数据不是代码 → 可被 Agent 自管理（GSimulator agents/*.json 已是同构实践）。
2. **权限收缩四档（强度递增）**：permission 映射（allow/ask/deny）→ 工具白名单 → 只读 agent → 隔离升级（同进程线程→子进程→OS 沙箱）。默认不需要进程级隔离，但必须预留 Executor 抽象（本地/子进程/容器可切换）。**权限传递单向：默认继承父级、可逐项收紧，子 Agent 不能给自己提权。**
3. **上下文管理**：隐藏 compaction agent + prompt-cache 不变量 + 写入式记忆块 + FTS 检索召回——语言无关，JVM 有成熟 SQLite FTS5 绑定。
4. **事件与 UI 解耦**：headless server + OpenAPI + SSE 总线 + 权限请求 HTTP 端点；最小事件集 = session.*/message.*/tool_call.*/permission.request|response/state.snapshot/error/heartbeat；再映射到 AG-UI。
5. **自管理闭环六要素**：分层配置合并 → JSON Schema 校验 → 原子写 + git 版控回滚 → 默认延迟生效（缓存友好）→ 高风险变更（增删 MCP=执行任意代码）走权限通道 → 审计 + 自检命令。
6. **扩展机制**：MCP-first（扩展即 MCP 子进程，按需拉起、空闲即关）；skills 承载知识型能力；进程内插件只放自己审过的代码（全信任，Letta mods 的教训）。
7. **轻量化**：单二进制/毫秒启动是 Rust/Bun 红利；Java 对应物 = jlink + AppCDS + CRaC（详第五章）；**真正的轻量思路 = 小 core + headless + 协议化扩展 + 前端可选**。

## 五、Java 技术栈注意点

### 5.1 JDK 版本与语言特性
- **基线 Java 21、运行时尽快上 JDK 25 LTS**（2025-09-16 GA；JDK 26 非 LTS）。编译目标 `--release 21`。
- **虚拟线程直接用**（JDK 21 final；agent runtime 是"极高 I/O 并发、低 CPU"负载的典型）。Pin 问题：JDK ≤23 的 synchronized 内阻塞会 pin，**JDK 24 JEP 491 已修复**——跑 21 时热路径锁（含 I/O 的）优先 ReentrantLock。【本机验证：虚拟线程开箱可用】
- **Structured Concurrency 至今仍是 preview（JDK 26 第六次预览）**——核心协议代码不要依赖；**Scoped Values 已在 JDK 25 转正**（JEP 506），可作 Agent 上下文（agentId/traceId/权限）传播方案。【本机验证：21 上两者均需 --enable-preview】
- **records + sealed interface + 穷尽 switch**：协议消息（JSON-RPC/MCP/A2A/AG-UI 事件）是封闭代数数据类型，这三件套是 Java 21 写协议代码的核心工具（官方 SDK 内部即大量嵌套 record）。
- String Templates 已撤销（勿用）；JDK HttpClient 覆盖 HTTP/2（本机验证）、SSE 手解（`BodyHandlers.ofLines`）、WS 客户端；JDK 无 WS 服务端 API。

### 5.2 网关层选型（轻量化的关键决策）
- **jdk.httpserver 官方自证"仅限测试/调试"**（JDK 25 javadoc 原文），无 HTTP/2/WS；但 stdio 优先架构里它够用于本地控制面（REST 管理口/健康检查/低并发 A2A REST/AG-UI 本地桥）。【本机验证：SSE 渐进输出正常，虚拟线程下 100 并发 SSE 长连接 1.6s 完成】
- **生产 HTTP 网关备选：Vert.x 5（只引 vertx-core，单模块覆盖 HTTP/1+2/WS/SSE）或 Helidon SE 4（纯虚拟线程模型，与 agent 代码心智一致）**。不引 Netty 裸拼、不上 Spring Boot。
- **核心论据："核心模块零 web 依赖，网关层可替换"**：MCP stdio 传输零依赖（官方 SDK 的 stdio 实现即如此）；官方 SDK 的 HTTP 服务端反而绑 servlet 容器/Spring，用 jdk.httpserver 做 MCP streamable HTTP 服务端需自写薄适配（POST JSON-RPC + SSE 两条路由，工作量小）；A2A 官方 SDK 本身是"传输可替换"的实证（jsonrpc/grpc/rest 三 transport + Vert.x HTTP client extras）；AG-UI 是纯事件协议。
- **设计推论**：核心模块只依赖"传输 SPI"接口 + stdio 实现；HTTP 网关做成独立模块（默认 jdk.httpserver 适配器、需要时换 Vert.x），shade 时按需并入。

### 5.3 JSON / JSON-RPC
- 统一 **Jackson 2.22.x**（2.x/3.x 双线并存，3.x 包名 tools.jackson；MCP SDK 聚合包 `mcp` 默认带 jackson3——**拆用 `mcp-core + mcp-json-jackson2`** 保持全工程 Jackson 2.x 单一惯例）。
- **不引入 jsonrpc4j**（停滞）；通用 JSON-RPC 三选一：手写 ~100 行 / 复用 MCP SDK 内置 JSON-RPC 层 /（A2A SDK 的 JSON-RPC 是 Gson 且标注 internal，不当通用库用）。
- 各 SDK JSON 现状：MCP=Jackson 可插拔；A2A=Gson 2.14（接受或 exclusion）；ACP=Jackson 2.22.2；AG-UI community=可插拔 Serializer。

### 5.4 子 Agent 隔离与沙箱（重点）
- **SecurityManager 已死**：JEP 411（17 弃用）→ **JEP 486（JDK 24 起永久禁用**：启动参数报错、setSecurityManager 抛 UOE），官方指明的出路 = 容器/OS 机制。【本机验证：getSecurityManager() 返回 null 且编译警告 deprecated for removal】
- **首选：进程级隔离（stdio 子进程）**——"子 Agent = 一个 stdio 子进程"恰好就是 MCP stdio 标准用法；隔离面 = 内存/崩溃/System.exit/资源；**权限模型落在网关**：spawn 参数 + 工具白名单 + 环境变量白名单 + 工作目录 + 联网开关，全部是数据、可被 Agent 自管理。
- **分级设计（推荐直接采用）**：L0 = stdio 子进程 + 超时 + 输出上限 + 环境白名单（默认）；L1 = + 独立 OS 用户 / 受限目录；L2 = + bwrap/容器网络隔离。bwrap（无特权 user-namespace 沙箱）对"低可信工具"（prompt 注入可操纵）特别合适。
- 进程内隔离（ClassLoader/ModuleLayer/WASM-Chicory）**无安全边界**，只放自己审过的插件。
- 成本参考：【本机实测】空闲 JVM RSS ≈ 38.7MB → 子进程尽量用原生工具，必须跑 Java 逻辑时用少量常驻工作进程复用。

### 5.5 轻量化发行与启动
- **GraalVM native image 不首选**：MCP/A2A 无官方支持（A2A 有 open bug #1032 证实会破）；**closed-world 假设与"Agent 自管理动态装载模块"根本冲突**；仅小 CLI 可试。
- **推荐混合路线**：主脑 = JVM 常驻（shade 单 jar + AppCDS + 可选 jlink 定制运行时【本机实测 java.base 52MB】）；子 Agent/工具 = 原生工具或少量 JVM 工作进程；秒起 CLI 才考虑 native image。
- shade 注意：ServicesResourceTransformer（SPI）、排除签名文件、minimizeJar 慎用；sqlite-jdbc native 库随 jar 解压。

### 5.6 事件存储（自研核心的基础设施）
- **首选 SQLite（WAL + busy_timeout）**：单文件可运维、写并发天然低（个人 Agent 场景）；纯 Java 洁癖选 H2（2.6MB 无 native）；DuckDB（85MB）只做只读分析副引擎。RocksDB/LMDB 在个人级 append-only 场景收益为负。【本机实测：SQLite/H2/DuckDB JDBC 建表写入查询全通过；WAL 生效】
- 表结构建议：`events(seq, ts, type, agent, payload_json)` + `snapshots(agent, version, state_json)`——事件即事实、快照即状态。
- **跨方言坑（实测踩到）**：SQLite 的 INTEGER PRIMARY KEY 自动递增、H2/DuckDB 不自动——建表语句写显式 IDENTITY，否则换引擎就炸。

### 5.7 配置即数据
- JSON + JSON Schema（`com.networknt:json-schema-validator`——**MCP SDK 自己也用它，一个依赖两用**）；HOCON/YAML 只作人类手工前端、加载时转换一次。
- 安全闭环：schema 校验 → 原子写（tmp + force + ATOMIC_MOVE）→ 读回验证 + `.bak` 回滚 → **配置空间按键前缀分级授权**（子 Agent 只许改 `agents.<id>.*`，不许碰 `runtime.*`）→ 落盘后广播 reload 事件 → 每次变更一条 append-only 审计事件。

### 5.8 可观测与 LLM 调用
- **OTel Java 1.65.0**（SDK 手动埋点优先于 javaagent；gen_ai.* 语义约定仍在演进，勿深绑字段）；**CloudEvents Java 5.0.0**（事件导出/路由时包装，与 A2A 生态互通）。
- **LLM 调用核心方案 = HttpClient + OpenAI 兼容 REST + SSE 手写（约 200 行，零依赖）**——适配一切 OpenAI 兼容端点（Ollama/vLLM/DeepSeek/GLM 等）；真正的复杂度在 tool-call 循环/上下文构建/限流重试，不在 HTTP 层。官方 SDK（openai-java 4.58/anthropic-java 2.61）放可选模块；langchain4j（1.20.0，升级节奏快）观望。

### 5.9 依赖最小化清单（核心模块六坐标闭环）
`mcp-core + mcp-json-jackson2 + jackson-databind + slf4j-api + networknt-json-schema-validator + sqlite-jdbc`——**六个坐标即可让"主 Agent + 多个 stdio 子 Agent + 事件存储 + 自管理配置"跑起来**。按需加：A2A SDK（JSON-RPC transport）、vertx-core（生产网关）、acp-core、AG-UI community、OTel/CloudEvents。显式不引入：jsonrpc4j、Spring Boot/Spring AI、langchain4j、DI 框架。

## 七、跨切面注意点总表（本报告的核心答案）

### 7.1 架构与模块边界
- core 窄腰、能力在边缘：核心只做循环/状态/权限/事件；工具=注册表、能力=MCP 子进程/插件/skills 按需加载（Hermes/Goose）。
- headless server + UI 可选：core 是无 UI 服务进程（OpenAPI + SSE），TUI/Web 是可选模块（OpenCode）。
- Maven 模块单向依赖：方向写死 + 双重检查（import 零命中 + pom 无依赖边）（GSimulator 判定法）。
- 协议层与工具注册表解耦：MCP/A2A/AG-UI 只是 AgentTool/ToolRegistry 的适配器（iBotMosire 原则）。

### 7.2 协议集成
- P0 只做 MCP+A2A+Skills+AGENTS.md；MCP 锁 2.0.1、3.0 升级列入债务、保留 hand-rolled 开关；新代码禁用 Roots/Sampling/Logging/legacy HTTP+SSE；A2A 先 JSON-RPC（CDI 决策点见 3.2）；AG-UI 薄适配层 + 手写最小事件子集兜底；事件面按 AG-UI 设计（现成平台反而不支持 AG-UI——先兼容就是差异化）；名字混淆坑（ACP 默认=Agent Client Protocol）。

### 7.3 子 Agent 模型
- 子 Agent = 数据不是代码（JSON Schema 校验模板 + 目录扫描；字段 description/prompt/model/工具白名单/权限映射/steps/超时）。
- spawn API：goal/context/role/allowed_toolsets/blocked_tools/working_directory/timeout + depth 限深 + 完整状态机（Hermes 模型）。
- **权限单调性**：默认继承父级、可逐项收紧，子 Agent 永远不能提权；防递归 delegate。
- 隔离四档：permission 映射 → 工具白名单 → 只读 agent → 子进程/OS 沙箱；Executor 抽象可切换。
- 子 Agent 可以是外部进程（stdio MCP 子进程）或外部 coding agent（claude-code/codex）——同一抽象。
- 防跑飞硬顶：maxTurns/maxToolCallsPerTurn/timeBudget + 进程树清理 + 配额记账。

### 7.4 大 Agent（Brain）
- 主循环 = tool-calling + 事件流记录；上下文构造四来源（会话历史 + FTS 记忆检索 + skills 渐进目录 + AGENTS.md/项目上下文）；隐藏系统 agent 做压缩；**prompt-cache 不变量**（历史只在压缩时可变，配置默认延迟生效）；反幻觉护栏（GSimulator 现成件）；工具结果溢出暂存 docId。

### 7.5 权限与身份
- 双维权限模型：身份维（token→guest/default/system）+ 工具维（requiredLevel/sensitive/destructive）+ per-Agent 维（工具白名单/参数范围）；执行入口才是最终边界（"没注入给模型≠不能执行"）；每子 Agent 独立最小凭证（不再共享单 default token）；拒绝即终局 vs 审批流可插拔（PermissionGate 接口：CLI 确认门/AG-UI HITL/auto-approve）；凭据目录写硬阻断；任何工具都不能关进程。

### 7.6 自管理闭环
- 配置即数据；六要素闭环（schema 校验 → 原子写 → 回滚 → 默认延迟生效 → 高风险变更走权限通道 → 审计）；Agent 自建/自改 skills（learning loop，allowed-tools 并入权限）；**自升级禁令**（Agent 不能替换自身二进制）；状态查询=最低权限。

### 7.7 事件存储与个人信息模型（自研核心）
- append-only 事件日志 + 快照 + 检索（event-sourced）；实体模型最小起步（Task/Conversation/Document/Claim/Evidence/Persona/World + GSimulator 分层与 @ 引用）；schema 版本化 + 迁移/修复工具（Hermes 经验）；事件词汇表对齐 AG-UI；存储选型：SQLite(WAL) 基线（见 5.6）。

### 7.8 安全
- 沙箱三档 ReadOnly/WorkspaceWrite/DangerFullAccess + 不可恢复黑名单常开（Codex）；**信任边界=进程边界**（SecurityManager 已死）；Prompt injection 当常态（工具输出一律不可信；高危工具白名单+参数范围+干跑预览；FIDES 信息流标签思想可借鉴）；网络面默认 127.0.0.1。

### 7.9 轻量化（贯穿一切）
- 核心六坐标依赖闭环（5.9）；能力按需拉起（MCP 子进程不用不占内存、工具组按需激活）；发行 = shade 单 jar + AppCDS + 可选 jlink；虚拟线程覆盖 I/O 面（21 上注意 pin）；工程门禁延续既有三件套。

### 7.10 测试与可观测
- 离线确定性测试（Mock 模型、假 Agent 子进程、事件重放）；协议合规进 CI（MCP conformance、A2A TCK）；结构化日志 + Prometheus 预留 + OTel 二期。

## 八、主要风险与坑

### 8.1 协议/SDK 成熟度
1. **MCP Java SDK 是 Tier 2 且滞后半个规范代**：2.0.x 追 2025-11-25，2026-07-28 在 3.x（预计 2026-09）→ 锁 2.0.1 + 按新形态设计 + 升级列债务。
2. **AG-UI Java SDK 只有社区版 0.1.0**：薄适配层 + 手写 SSE 兜底。
3. **ACP 0.17.0 仍在快速迭代**：二期再用，不在核心绑定。
4. **A2UI early preview**：一期不依赖；MCP Apps 是更成熟的"工具自带 UI"路线。
5. **ANP/UCP/AP2**：观察不绑定。

### 8.2 协议演进本身
6. MCP 半年一大改：弃用清单（Roots/Sampling/Logging/legacy HTTP+SSE）新代码绝不能碰；所有"2026 规范参考实现"随 3.x SDK 重审。
7. 命名混淆坑：ACP=Agent Client Protocol；老 IBM ACP 已归并 A2A。
8. 版本协商教训：GSimulator 手写 MCP 硬编码 2024-11-05 无协商（WDMosire 已批评）——官方 SDK 直接消灭此类问题。

### 8.3 Java 平台特有
9. **SecurityManager 已移除 → 子 Agent 隔离必须进程级/OS 级**，进程内"逻辑隔离"只能防君子。
10. GraalVM 与反射库/协议 SDK 不兼容 + closed-world 与动态装载冲突 → 不首选。
11. 虚拟线程 pin（JDK 21 上 synchronized 内阻塞）→ 热路径用 ReentrantLock；JDK 24+ 修复。
12. 子进程泄漏：必须进程树级清理（iBotMosire SIGTERM→destroyForcibly 模式）。

### 8.4 自管理带来的坑
13. **权限单调性**：Agent 不能授予自己/子 Agent 超过自身的权限；自管理工具本身分级（GSimulator 现缺此边界）。
14. **自升级禁令**：Agent 可管配置/skills/子 Agent，不能替换二进制（一次坏更新=自杀）。
15. 配置写坏兜底：原子写 + schema 校验 + last-known-good 回退 + 全量审计事件。

### 8.5 安全
16. Prompt injection 是常态：工具输出一律不可信；高危工具白名单+参数范围+干跑预览。
17. 凭证平面：provider key/账号 token 与 Agent 可见数据分离；每子 Agent 独立最小凭证。
18. 网络暴露面：MCP/A2A/AG-UI 默认 127.0.0.1；对外开口独立授权限流。

### 8.6 数据与记忆
19. 事件存储 schema 演进：版本化 + 迁移工具（Hermes state_schema/repair）。
20. 上下文膨胀：结果溢出暂存 + 工具目录分页/工具组激活 + micro-compaction 三者都要。
21. "假推送"教训：subscriptions/listen 真推送从第一天做（AG-UI/A2A 流式语义都要求真推送）。

### 8.7 生态与合规
22. 许可证：SDK 全宽松；n8n/Dify/Open WebUI 只抄设计；Letta 品牌资产排除。
23. 社区数字不可靠：stars 已实测但 MAU 类不背书；选型看源码与 SDK 生态不看 stars。
24. AutoGen 已死线：不要以其为基础；MAF 无 Java，只取思想。

### 8.8 工程
25. 模块依赖方向钉死 + 双重检查。
26. 测试全离线（Mock 模型/假子进程/事件重放）——依赖外部 LLM 的 CI 是彩票。
27. 协议合规进 CI（conformance/TCK）——避免"手搓又搓歪"（三代手写 MCP 的历史教训）。
