# 0.2.7 Java 运行时与发行设计

> 开发阶段使用 `0.2.7-SNAPSHOT`，进度在 `dev/0.2.7` 分阶段提交和推送。用户确认可用后才切固定版本并执行正式发布。

## 使用路径与模块边界

| 用途 | 对外制品 | 装配方 |
|---|---|---|
| 简单 Agent 和工具 | `agentlib-mosire` | AgentLib 提供轻量默认装配，宿主注入模型和工具授权 |
| 工作区、文档 | `workspace-mosire`、`docs-mosire` | 宿主声明实际调用的库并注册需要的能力 |
| 完整 Java Agent 运行时 | `brain-mosire` | Brain 提供模型、会话、存储、工具和权限的装配入口 |
| 独立服务 | `mosire-server-<version>.zip` | Main 使用 Brain 的装配入口，负责命令行、配置读取、网关和宿主进程 |

调用方向为 `Main → Brain → AgentLib`，Brain 继续消费 Workspace 和 Docs。Bash 通过独立 PF4J 插件装载。默认权限显式收窄，宿主传入模型客户端与权限，子 Agent 保持进程边界与权限单调性。现有三库从 0.2.2 起的公开签名、旧坐标和已有数据库读写路径承担兼容。外部 Java 入口归现有 Brain 模块。

## 第一阶段 发行目录与启动回滚

在 0.2.5 的发行审计中，`MainMosire/pom.xml` 把不同版本的 Bash JAR 累留到同一个默认插件目录。PF4J 的 `Plugin-Id` 一致，服务启动退出码为 1。`App.start` 在 AdminREST 启动后装配 A2A，失败路径遗漏已打开的 AdminREST。此外第二条 SQLite 连接的打开和事件总线都需要纳入回收范围。

- 每个资源取得后立即登记关闭动作。启动失败按取得的逆序尝试关闭所有资源，关闭异常保留为原启动异常的 suppressed exception。先打开事件与会话库，网关、运行时、子进程和插件在其后装配。各工厂负责自己返回之前的回收。
- 成功启动后由现有 `App.close()` 接管资源，保持服务关停时的事件和生产者顺序。运行模式、HTTP 端口与插件目录解析沿用现行契约。
- 构建仅清理 `MainMosire/target/plugins` 下本项目命名的旧版 Bash 制品，保留同版本和其他插件。随后由 Maven 复制本次构建的对应插件。默认开发入口仍为 `target/mosire.jar` 与同目录 `plugins/`。
- 发布压缩包明确选取本次主 JAR、同版本插件、启动指南、示例模板及 LICENSE/NOTICE。附带的模板选用已跟踪且无密钥的示例。源码包和 Bash JAR 的构建插件锁定版本。正式发布的工作流在后续阶段接线。

验收用干净发行目录启动离线模型，检查健康、对话、事件和 Bash 装载，随后覆盖两种故障。其一是在默认构建目录放置旧 Bash 制品和一个其他来源的插件文件，构建只去掉旧 Bash，ZIP 仍精确装入当次插件。其二是在同进程占用 A2A 端口，断言启动失败后 Admin 端口可立即重新绑定，再正常启动。关闭回收的失败测试在统一验收阶段补上。

本阶段生产文件由启动与打包实现任务持有 `MainMosire/src/main/java/io/mosire/main/app/App.java`、`MainMosire/pom.xml`、`MainMosire/src/assembly/`、根 `pom.xml` 中构建插件部分。`docs/guides/run-server.md` 由控制方维护。
