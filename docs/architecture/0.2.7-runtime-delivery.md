# 0.2.7 Java 运行时与发行设计

> 开发阶段使用 `0.2.7-SNAPSHOT`，进度在 `dev/0.2.7` 分阶段提交和推送。用户确认可用后才切固定版本并执行正式发布。

## 使用路径与模块边界

| 用途 | 对外制品 | 装配方 |
|---|---|---|
| 简单 Agent 和工具 | `agentlib-mosire` | AgentLib 提供轻量默认装配，宿主注入模型和工具授权 |
| 工作区、文档 | `workspace-mosire`、`docs-mosire` | 宿主声明实际调用的库并注册需要的能力 |
| 完整 Java Agent 运行时 | `brain-mosire` | Brain 提供模型、会话、存储、工具和权限的装配入口 |
| 独立服务 | `mosire-server-<version>.zip` | Main 使用 Brain 的装配入口，负责命令行、配置读取、网关和宿主进程 |

调用方向为 `Main → Brain → AgentLib`，Brain 继续消费 Workspace 和 Docs。Bash 通过独立 PF4J 插件装载。默认权限显式收窄，宿主传入模型客户端与权限，子 Agent 保持进程边界与权限单调性。现有三库从 0.2.2 起的公开签名、旧坐标和已有数据库读写路径承担兼容。外部 Java 入口归现有 Brain 模块。

## 第一阶段 发行目录与启动回滚

在 0.2.5 的发行审计中，`MainMosire/pom.xml` 把不同版本的 Bash JAR 累留到同一个默认插件目录。PF4J 的 `Plugin-Id` 一致，服务启动退出码为 1。`App.start` 在 AdminREST 启动后装配 A2A，失败路径遗漏已打开的 AdminREST。此外第二条 SQLite 连接的打开和事件总线都需要纳入回收范围。

- 每个资源取得后立即登记关闭动作。启动失败按取得的逆序尝试关闭所有资源，关闭异常保留为原启动异常的 suppressed exception。先打开事件与会话库，网关、运行时、子进程和插件在其后装配。各工厂负责自己返回之前的回收。
- 两处现有工厂纳入同一回收契约。`McpToolSource.connect` 在新 client 握手失败时关闭该 client，已装配的调用方仍可关闭 source。`A2aHttpServer.start` 在端口绑定后对卡片生成和 server 启动失败负责，已返回的网关由装配方关闭。保留各自原始失败和关闭异常。
- 成功启动后由现有 `App.close()` 接管资源，保持服务关停时的事件和生产者顺序。运行模式、HTTP 端口与插件目录解析沿用现行契约。
- 构建仅清理 `MainMosire/target/plugins` 下本项目命名的旧版 Bash 制品，保留同版本和其他插件。随后由 Maven 复制本次构建的对应插件。默认开发入口仍为 `target/mosire.jar` 与同目录 `plugins/`。
- 发布压缩包明确选取本次主 JAR、同版本插件、启动指南、示例模板及 LICENSE/NOTICE。附带的模板选用已跟踪且无密钥的示例。源码包和 Bash JAR 的构建插件锁定版本。正式发布的工作流在后续阶段接线。

验收用干净发行目录启动离线模型，检查健康、对话、事件和 Bash 装载，随后覆盖两种故障。其一是在默认构建目录放置旧 Bash 制品和一个其他来源的插件文件，构建只去掉旧 Bash，ZIP 仍精确装入当次插件。其二是在同进程占用 A2A 端口，断言启动失败后 Admin 端口可立即重新绑定，再正常启动。关闭回收的失败测试在统一验收阶段补上。

本阶段生产文件由启动与打包实现任务持有 `MainMosire/src/main/java/io/mosire/main/app/App.java`、`MainMosire/src/main/java/io/mosire/main/gateway/a2a/A2aHttpServer.java`、`AgentLibMosire/src/main/java/io/mosire/agentlib/mcp/McpToolSource.java`、`MainMosire/pom.xml`、`MainMosire/src/assembly/`、根 `pom.xml` 中构建插件部分。`docs/guides/run-server.md` 由控制方维护。

## 第二阶段 可嵌入的 AgentLib 和 Brain

`AgentLoop` 当前由宿主提供窗口、编排器、分派器和停因策略。Brain 的 `AgentRuntime` 委托 `AgentPipeline` 执行并写回历史，`App` 当前拥有 SQLite、总线和网关。会话指针位于现有会话库内，按数据目录单写者使用。0.2.7 沿用 `events.db`、会话指针和现有事件载荷。

### AgentLib 入口

- `SimpleAgent.create(AgentConfig, LlmClient)` 建内存会话并默认没有可调工具。带 `ToolRegistry`、`AgentPermissionSet` 的重载借用注册表，身份采用配置 id，调度通过 `ToolCallAuthorizer.standard()` 实施。生效工具面取配置白名单与授权白名单交集，拒绝名单取并集，保留角色、操作、资源、只读等既有权限约束。授权缺席及工具要求审批时按现有判定拒绝。
- `chat(String)` 在同一窗口连续运行，同一实例由调用方串行。请求按 system、窗口、本轮输入组装，工具结果用原调用 id 写回。沿用 `AgentConfig` 的模型往返上限、单次响应工具项上限、墙钟预算及会话 token 额度。墙钟预算在往返边界检查，工具执行独立使用原硬超时。整批超限和额度终止时为未执行调用补工具失败结果，以便下次续聊。LLM 不成功的往返按 `AgentLoop` 的失败出口返回。
- `AgentTool.of(name, description, schema, spec, handler)` 适配 Java 函数，调用者显式选 `ToolSpec`。已有完整 `AgentTool` 接口继续供声明角色、资源和审批等需求使用。修订 `AgentConfig` 默认轮数和 `TurnResult.turns` 的文档，后者计本用户回合内成功模型往返数。

### Brain 入口

- `AgentRuntime.builder(AgentSpec, LlmClient)` 在现有管线前装配，`dataDirectory(Path)` 由 Runtime 打开和关闭资源，`storage(RuntimeStorage)` 借用调用者已打开的资源。二选一，在打开资源前校验配置。默认新建工具注册表，权限默认空的只读授权，显式传入的模型客户端、工具注册表和审批通道由宿主拥有。
- `RuntimeStorage.open(Path, boolean persistConversations)` 统一创建数据目录、SQLite 事件库、可选会话库和事件总线。打开中途失败关闭已取得的资源。关闭时尝试关闭全部，保留异常因果，重复关闭安全。事件库和会话库沿用同一路径 `events.db`。未持久化模式用于 demo 与子体，主服务使用已有活动会话指针续接。调用方在同一实例串行执行 `chat`、`resetSession`、压缩请求和 `close`，`cancel` 保持可从其他线程请求。
- Builder 用命名选项装配注册表、权限、上下文装配器、工具配置、初始会话 id、审批编排器、决策桥、跨进程提交口和压缩器。审批编排与主侧决策桥要求会话落库，以继承生产路径和 demo 分叉的原语义。Builder 将有权使用的角色与资源传给现有管线。外部通过 `queryEvents(EventQuery)` 查看此运行时的事件。
- Main 的 `App` 和 `SubagentProcessMain` 通过同一 Builder 借用自己持有的 RuntimeStorage，网关与子进程的启动命令由 Main 装配。运行时关闭成功后，拥有方关闭存储。Main 的外部 MCP stdio 默认值、demo 的工具上下文、子进程终局先落库后收尾，以及默认压缩的启用分叉沿用原口径。向主 Agent 管线和本机决策提交口传入宿主 `tool.executionTimeoutMs`，非法值沿用 authorizer 的缺省规则。
- Workspace 和 Docs 的能力仍由宿主提供挂载、权限与共享注册表，使用 `WorkspaceTools.all` 和 `DocsTools.all`。审批通道显式提供。启用子进程编排时，宿主注入已经绑定权限和工具的 `SubagentManager` 工具，以及真实的 `AgentCommand`/执行器。命令行、传输和密钥来源属于宿主，子 Agent 的权限单调性判断仍由现有编排器实施。

验收同时覆盖仅 AgentLib 的离线对话、允许/拒绝工具与失败回填，以及 Brain 从外部项目开库、会话重启、借用和拥有资源、关闭异常、权限缺席拒绝。Main 正常服务、demo 和子体原测试继续有效。独立调用方能用相同工具注册方式按需加入 Workspace 或 Docs。

本阶段生产文件所有权为 AgentLib 的 `SimpleAgent`、`AgentTool`、`AgentConfig`、`TurnResult`，Brain 的 `AgentRuntime`、`RuntimeStorage`，以及 Main 的 `App`、`SubagentProcessMain`。接口与资源所有权的细节在统一验收阶段落测试。
