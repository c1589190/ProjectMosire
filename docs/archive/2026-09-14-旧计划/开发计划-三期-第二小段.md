| | 旧（S1 及以前） | 新（本段 S2） |
|---|---|---|
| 主证据 | **离线单测全绿**（`mvn verify` 全量跑） | **使用模式实跑**：真进程 + HTTP 对话 + 日志/事件库判读 |

（`App` 恒定用 `MAIN_CONVERSATION_ID`，重放旧会话）。而全量离线门禁跑了整个三期，从未红过。

## 一、D29 使用模式测试范式（冻结）

1. **运行形态**：`java -jar MainMosire/target/mosire.jar run --data-dir <数据目录> [--templates-dir configs/agents]`
   ——**不带任何 `--fake*`**；配置与密钥取自 `<数据目录>/config.json`（D20/D23 不变）。
2. **对话入口**：HTTP 调试面（D25）——`POST /api/chat` 提交、`GET /api/chat/{runId}` 取终态与 `result.text`、
   `POST /api/chat/session` 重置、`GET /api/chat/session` 读当前会话 id。
   **对话由人/子代理自然语言驱动**，不是脚本回放——要测的就是真实使用下的行为。
3. **判据三方互证**（缺一不可）：
   - **HTTP**：run 终态（`finished`/`failed`/`cancelled`）+ 回复原文；
   - **日志**（stdout/stderr）：启动行、告警、异常栈、看门狗；
   - **事件库**（`<数据目录>/events.db`）：`llm.call`（`model`/`usage`）、`tool.call`/`tool.result`、`conversation.turn`、`conversations`/`messages` 表。
   > 只看回复文本不算数（可能是骨架/占位）；**每个结论都要有一条库或日志侧的硬证据**。
4. **离线用例的定位**：默认 `./mvnw verify` 仍须离线可跑（`--demo`/`--fake*` 语义不变），
   但它是**回归钉**，不是验收主证据；**改动只跑相关单条用例**（`-Dtest=<类名>`），不跑全量。
5. **不变的部分**：`--demo` 零变化；密钥不进日志/异常/事件/argv/env/stdio（D23/D24 一字不改）。

> **新的措辞纪律**：文档里不再出现"测试禁止依赖外部 LLM/网络"这类**绝对禁止**——
> 它此前被读成"不能用真模型测"，把三期证据一直压在测试模式里（旧 D22）。离线是**门禁**，不是**禁令**。

## 二、测试台（S2-1）——`scripts/usage-test.sh`

**定位**：与 `smoke-live.sh`（P3-4，**固定断言序列**）互补——本台架**不做断言**，只把程序跑起来、
把交互口交给测试员、把说过的每句话与程序回的每个字**原样存证**。判读是人的事（D29 §一.3 三方互证）。

**子命令**（一个数据目录 = 一个长期实验台，跨重启场景靠它）：

```
start [--name n] [--data-dir p] [--config p] [--jar p] [--templates-dir p|--no-templates]
      [--port n] [--max-seconds n] [--xmx m] [--fresh]
say [--timeout s] <消息>       # 消息传 "-" 从 stdin 读
session | reset | db [--query SQL] | scan | logs [--lines n] | status | stop
```

**证据包**：`<数据目录>/usage-test/<时间戳>/`（每次 `start` 一包，故同一数据目录重启两次不互相覆盖）：

| 文件 | 内容 |
|---|---|
| `turns/NNNN.request.json` / `NNNN.snapshot.json` / `index.tsv` | 每回合：原话 / 原始快照（`status`+`result`）/ 索引（runId、stopReason、turns、toolCalls） |
| `main.log` | 进程 stdout+stderr（启动行、告警、异常栈、看门狗） |
| `db/{events-dump,messages-dump}.tsv`、`db/child-<id>-events.tsv` | 事件库 / 会话库 / **各子体库**快照 |
| `session-get.json`、`reset-NN.json` | 会话读/重置原文 |
| `scan.txt`、`PACK.md` | 密钥扫描结果、证据包索引（含"怎么看"与回合索引） |

**硬约束（脚本自己守，不靠人记得）**：
- `start` **拒绝**在已有 mosire 进程时启动（`pgrep -f mosire\.jar` 全局自检）——本机只许一个真进程；
- `start` **拒绝**数据目录不在 gitignore 内（证据包含 600 配置副本，不许落进受控目录）；
- `start` 回源校验骨架占位串仍与 `App.DEFAULT_LLM_REPLY` 一致（脚本常量防漂移）；
- 进程组级清理（`setsid` + 杀组），`stop` 后报残留；
- `scan` 扫数据目录**全部文件**（排除各 `config.json` 自身）——日志、事件库、子体库、证据包一网打尽，0 命中才 PASS；
- 骨架探针内建：`say` 的回复一旦命中占位串就**当场提示**（假模型退化的第一现场）。

**复用件来源**：`scripts/smoke.sh`（进程启动/端口解析/进程组清理）、`smoke-live.sh`（600 配置拷贝、
墙钟看门狗、密钥扫描做法）、`s1b-explore.sh`（多轮节奏）。看门狗仍由脚本外挂（不靠 LLM 守规矩）。

## 四、执行方式（S2-3，子代理）

- **子代理测试员**：一个场景（或一组）一个子代理，职责 = 起进程 → 自然语言对话 → 取证 → 交《使用测试报告》。
- **报告格式**（沿用 S1-B 纪律）：现象 / 复现步骤（逐字命令与消息原文）/ 期望 vs 实际 / 严重度 / 证据在哪（日志行或 sqlite 查询）。
- **控制者（我）**：抽样**独立复现**每条发现——**复现不了的退回，不算数**；A 档缺陷派子代理修。
- **串行纪律**：同一时刻只有一个子代理起真进程或跑 Maven；子代理一律默认模型（deepseek-flash），不传 model 覆盖。
- **不再做二次评审轮**（用户 2026-09-12 纪律）：修完 = 复测同场景通过 + 补一条离线判别性用例。
