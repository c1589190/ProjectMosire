## 一、目标与范围

**做**（五块，按依赖顺序）：

- **A 身份穿透与锚点修正（硬前置）**：
  `ToolContext` 携带调用者身份（`instanceId` + `depth`，缺省 = 主 Agent，4 参构造保持既有调用点零改动）；
  `SubagentInstance` 增 `parentInstanceId`；`spawn_sub_agent` 把调用者身份/权限集传进 `SubagentManager.spawn`；
  `checkMonotonicity`/`checkDepth` **改为锚到调用者**（修 `设计-Bash工具与工作目录围栏.md` §1.4 的构造期常量缺陷）；
  派发口对非 SYSTEM 开放（`kill`/`list` 维持 `systemOnly`——跨分支防护依赖 S3 的 subtree 判定）。
  **D28 基础项一并落地**：`agents.maxDepth`（总层数口径 3 ⇒ 子深度上限 2）/ `agents.maxChildrenPerInstance` /
  `agents.maxInstances`，越界 `BUDGET_EXHAUSTED`（消息含"需求/剩余/上限"三个数），配置值坏 ⇒ **启动即响亮失败**。
- **B 资源作用域维度（`fs` = 目录围栏）**：`ResourceScopeMap` 值类型 + `AgentPermissionSet` 第 7 维 +
  `PermissionChecker.isSubset` 新维（子 ⊆ 父）+ 请求面 `allowedDirs` + 模板可选字段 `allowedWorkingDirs`；
  越界 ⇒ `permission.denied` + `SubagentRejectedException`（**响亮**，`DIR_NOT_ALLOWED`）；
  主 Agent 缺省不限（裁决 ①），子体缺省继承父级（裁决 ②）。**record 与模板字段同批改**（否则老模板装载失败）。
- **C 工具内细粒度权限 SPI（本段的核心交付）**：按 `设计-审批与工具内权限.md` §2.5 落三条：
  ①声明式 `AgentTool.resources()`（`ResourceManifest`：命名空间 + 默认策略）；
  ②命令式 `ToolContext.resources().require(op, ResourceId)` → 拒则 `ResourceDeniedException` → `RESOURCE_DENIED`；
  ③`AgentTool` 契约注释更正（"不做工具名级判断；资源级判定走注入的 authorizer，工具不得自行放行"）。
  **判别性样本**：造一个**测试用插件样工具**（不入产品出厂），声明 `plugin:<id>/data` 命名空间，用两条用例证明
  "同一工具、同一参数、换调用者 ⇒ 一个放行一个拒"。
- **D bash 下放与三层围栏**：注册面加 `ShellTool` 到模板白名单（**出厂模板仍不给**，裁决 ⑤）；
  L1 参数面硬拒（受限调用者的 cwd 解析：绝对路径出 scope、`..` 词法越界 ⇒ `DIR_NOT_ALLOWED`）；
  L2 起点固定（子进程 `SpawnSpec.workingDir` 落 scope 首根）；L3 OS 沙箱（`unshare -m` + bind + `chroot` +
  `setpriv --bounding-set=-all --no-new-privs`，配方见底稿附录 A）；`tools.bash.sandbox = off | require`，
  **受限调用者一律 `require`；不可用 ⇒ `SANDBOX_UNAVAILABLE` 硬失败**（裁决 ③）。
- **E 使用模式验收 V1~V9**（底稿 §五）+ 每块一条**变异即转红**用例。

**不做**：审批改动（S4 已闭环，本段只复用）；完整 D27 血缘/subtree/读侧同判（归 S3）；符号链接完备防线
（L1 只做词法 + 根 realpath）；命令字符串扫描（假防护，设计 §2.1）；插件热重载。
