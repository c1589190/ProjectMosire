## 三、AgentLibMosire —— 通用 Agent 工具包（P0 主体之一）

> 目录已存在（空）。契约：不 import brain/main 任何包；无 Agent 概念（无"会话/循环/编排"——那些在 Brain）；任何程序可单独依赖。

### 3.1 `io.mosire.agentlib.tool` —— 工具系统机制
- `AgentTool`（唯一工具接口：`name()/description()/jsonSchema()/execute(ToolContext)`）、`ToolContext`（调用者身份 + 权限集 + 配置注入点）、`ToolResult`（`ok(String)`/`error(code,msg)`/资产引用 `docId` 暂存语义）。
- `ToolRegistry`：注册/查询/分组（`ToolGroup` 按需激活）、工具目录分页快照（防上下文膨胀，报告 7.4）。
- `ToolExecutionGuard`：执行入口最终边界——三要素（requiredLevel/sensitive/destructive）逐次校验 + `PermissionGate` 链（`auto-approve` / `ConfirmGate` / `DenyGate`）；拒绝即终局无审批流（可插拔 ApprovalGate 供 AG-UI HITL）。
- 迁移：GSimulator `gsim-agentsmanager` 的 AgentTool/ToolRegistry/ToolExecutionGuard/ToolGroupManager（语义照搬，实现重写为 Java 21 风格）。

### 3.2 `io.mosire.agentlib.mcp` —— MCP 适配（双向）
> API 依据：MCP SDK 2.0.1 源码 jar 抽查（mcp-core 2.0.1 无 `StreamableHttpServerTransport`；stdio 服务端类名=`StdioServerTransportProvider`；`mcp-json-jackson2` 经 `META-INF/services` 自动装配，`McpJsonDefaults.getMapper()` 即得 Jackson2 mapper；`Tool.builder(String name, Map<String,Object> inputSchema)` 直接传 schema 映射；`ServerParameters` **无工作目录字段**）。
- `McpToolSource`：官方 client 连接外部 MCP stdio server —— `McpClient.sync(new StdioClientTransport(ServerParameters.builder(cmd).args(...).env(...).build(), McpJsonDefaults.getMapper()))`（config 驱动 `McpClientLink`：启动超时/空闲回收/输出上限），`listTools()`→`callTool()` 映射为 `AgentTool` 注册进 Registry；`tools/list_changed` 经 `.toolsChangeConsumer(...)` 同步增删。
- ⚠️ 工作目录：`ServerParameters` 无 cwd 字段（内部 ProcessBuilder 只设 command+env）→ 子 Agent 进程的 cwd 由我们自己的 `SubprocessManager` 控制（M2 使用同 jar `agent` 子命令 + stdio 连接，不依赖 ServerParameters 的 cwd；仅当需要 cwd 时继承 `StdioClientTransport` 重写 `getProcessBuilder()`）。
- `AgentToMcpServer`：`McpServer.sync(new StdioServerTransportProvider(McpJsonDefaults.getMapper()))` + `.toolCall(McpSchema.Tool.builder(name, schemaMap)...)` 暴露 Registry 内 `AgentTool`（stdio；供子 Agent 进程/外部客户端消费）；运行时增删走 `McpSyncServer.addTool/removeTool`（自动发 `notifications/tools/list_changed`）。
- `mcp.mode=hand-rolled|sdk` 开关保留（兜底手写 JSON-RPC 层来自 iBotMosire，逐月轮换）。
- 弃用边界：新代码禁用 Roots/Sampling/Logging/legacy HTTP+SSE（D5）；2.0.1 不含 2026-07-28 特性（server/discover/头路由），3.0 发布即评估（§九.1）。

### 3.3 `io.mosire.agentlib.llm` —— 模型连接
- `LlmClient`（接口）、`OpenAICompatibleLlmClient`（JDK HttpClient + SSE 手解流，约 200 行；Streaming/非流式 + tool_calls 透传）、`ModelRoute`（provider 注册表：baseUrl/model/apiKey 引用密钥表）、`LlmQuota`（token 记账/费用上限，超限抛配额异常——brain 层触发 kill）。
- 测试件：`FakeLlmClient`（固定响应序列/record 脚本），放 agentlib 测试 jar 或 main 的 test 里（被 brain/main 共用）。

### 3.4 `io.mosire.agentlib.permission` —— 身份与权限集
- `AccessToken`（guest/default/system 三级）、`AgentPermissionSet`（grantedTools/deniedTools/toolParamScopes（如只允许某 worldId）/readonly 只读 agent/独立凭证引用）、`PermissionChecker`（单调性校验器：子集关系判定，供 Brain 拒绝提权）。
- 审计：每次校验通过/拒绝写事件（`AuditEvent`）。

### 3.5 `io.mosire.agentlib.config` —— 配置即数据
- `ConfigStore`：分层配置合并（`configs/config.json` ← `agents/<id>.json` ← 环境变量覆盖）；JSON Schema 校验（networknt 2.0.4，依赖 mcp SDK 所需版本；见偏差记录）→ 原子写（tmp+fsync+ATOMIC_MOVE）→ 读回校验 + `.bak` 回滚 → 广播 `config.changed` 事件。
- **按键前缀授权**：`agents.<id>.*` 由拥有者写；`runtime.*`/`keys.*` 仅 system；schema 定义在 `config-schema/`。
- 密钥表：`keys.*` 存引用（环境变量/文件），不进工具可读范围。

### 3.6 `io.mosire.agentlib.event` —— 事件存储（自研核心基础设施）
- `EventStore`（SQLite WAL + busy_timeout=5000）：`events(seq INTEGER PRIMARY KEY AUTOINCREMENT, ts TEXT, type TEXT, agent TEXT, payload TEXT, correlation_id TEXT)` + `snapshots(agent, version, state_json)`（DDL 写显式 IDENTITY 兼容 H2/DuckDB——实测坑，报告 5.6）；`EventBus`（进程内 pub/sub，虚拟线程分派）；审计查询（按 agent/type/correlationId）。
- 检索：`events_fts`（FTS5）供记忆检索。
- 事件词汇表第一批：`agent.lifecycle`、`conversation.turn`、`tool.call`、`tool.result`、`decision`、`config.change`、`skill.load`、`memory.recall`、`permission.denied`（对齐 AG-UI 命名习惯）。

### 3.7 `io.mosire.agentlib.store` —— 对话存储
- `ConversationStore`：`Conversation`/`Turn` 持久化（同一 SQLite 库，表 `conversations`/`messages`）；**prompt-cache 不变量**：历史只追加不改写、压缩产生的替换只发生在显式 `compact` 记录之后（报告 4.2/7.4；供 Brain 实现）。
- 接口默认实现 SQLite；Brain 唯一消费方。

### 3.8 `io.mosire.agentlib.proc` —— 进程管理
- `SubprocessManager`：spawn（命令/env 白名单/工作目录/输出上限）、心跳（stdout 周期 ping 或父进程存活检测）、SIGTERM→超时→进程树 `destroyForcibly`（iBotMosire 模式）、优雅退出；启动 jar 子 Agent 的默认模板方法。

## 四、BrainMosire —— Agent 运行时（P0 主体之二）

> 契约：只依赖 AgentLib；不含网关（HTTP 在 Main）；"同一个类"同时服务主 Agent 和子 Agent（差异=配置）。

### 4.1 `io.mosire.brain.runtime`
- `AgentRuntime`：一个 Agent 实例的编排根（id、配置、permissionSet、ModelRoute、context 等装配）；`AgentConfig`（json schema：`id/description/prompt/model/tools{allowed,denied}/permission/steps/timelimit`——数据不是代码，D10）。
- `AgentPipeline`（brain 内部）：`ContextAssembler` → `LlmClient` → tool-call 解析 → `Guard` → `ToolRegistry` 执行 → 结果 → 事件；循环终止条件（FINISH/无 tool call/硬顶）；反幻觉护栏（伪造 `[TOOL_RESULT]` 拦截、finish_action 强制收尾、连续空轮中止、结果溢出暂存 docId——GSimulator 现成件）。

### 4.2 `io.mosire.brain.context`
- `ContextAssembler`：四来源组装（会话历史 + 记忆检索 + skills 渐进目录 + AGENTS.md/项目上下文）+ 工具目录（激活组/分页）+ 配额预算提示；组序固定（保 prompt-cache 前缀稳定）。
- `Compactor`：阈值触发（token 预算门）；三档：micro-compaction（丢弃中段）→局部摘要（隐藏 Summarizer 配置/用同 runtime 但只读、无工具）→ 快照续接；压缩产物为 `conversation.compact` 事件。

### 4.3 `io.mosire.brain.memory`
- FTS5 `memory_fts` 检索（K=8），结果注入 context；跨 `agent.*` 共享库（权限过滤：检索结果按调用者 permissionSet 过滤后可见）。
- 写入：`remember(topic,text)` 工具 → `memory` 表 + 索引；摘要策略（按需）。

### 4.4 `io.mosire.brain.subagent` —— 子 Agent 编排（灵魂）
- `AgentTemplateStore`（`skills-agent*/子 Agent 模板目录`，Schema 校验，一个文件一个 Agent）＋ `AgentRegistry`（内存态：模板→实例 map）。
- `SubagentManager`：
  - spawn：`SubagentLaunchRequest{goal/context/role/allowed_toolsets/blocked_tools/working_directory/timeout/depth}`（Hermes 模型）；
  - 生命周期状态机：`CONFIGURED→SPAWNING→RUNNING→(BLOCKED→RUNNING)→TERMINATING→(FINISHED|FAILED|KILLED)`；崩溃恢复=状态在 Event Store，重启续写;
  - **单调性检查**（spawn 时校验子集关系：allowed ⊆ 父级 allowed·denied 必为父级 denied 子集·工具参数范围不越界；否则拒绝 spawn）——红线实现点 1；
  - 深度限制（默认 4，超限拒绝）；
  - `AgentExecutor` 抽象：`SubProcessExecutor`（默认，同 jar `agent` 子命令 + MCP stdio 连接）/`InProcessExecutor`（测试）/（预留 `ContainerExecutor`）；
  - 防跑飞：硬顶 + 配额记账 + 进程树清理。
- 注意：`spawn_sub_agent`/`kill_sub_agent` 仅为 system 级工具（调用者=grantedTool）。

### 4.5 `io.mosire.brain.skills`
- `SkillCatalog`：目录扫描（`skills/<name>/SKILL.md`）；三档渐进披露（catalog~50-100token 元数据 → 激活载正文 <5000token → references/scripts 按需）；frontmatter 校验（name≡目录名、description 1-1024）；**`allowed-tools` → 该技能调用者权限约束**（映射进 ToolContext）；`learn_skill` 工具（learning loop 使能，写操作默认延迟生效+git 版控回滚——MemFS 思想，走 ConfigStore）。

### 4.6 内置工具集（brain 注册，级别与标记）
| 工具 | 级别/标记 | 说明 |
|---|---|---|
| probe_status/list_agents | guest | 状态查询=最低权限（iBot H8） |
| spawn_sub_agent / kill_sub_agent / list_sub_agents | system/ destructive | 编排 |
| read_memory / remember | default | 记忆 |
| call_mcp_tool（透明直连）+ mcp_tool_catalog | default | 外部 MCP 工具入口（经 Registry 实际按名暴露） |
| config_get / config_put | default；`runtime.*` 前缀仅 system | 自管理配置（走 ConfigStore 闭环） |
| skill_load / skill_learn | default | skills |
| event_query / audit_query | guest（只读）/system（全量） | 事件存储查询 |
| send_user_message | default / sensitive | AG-UI 出口（Main 桥接） |

## 五、MainMosire —— 入口/网关（P0 主体之三）

### 5.1 `io.mosire.main.app`
- `Main#main`（`picocli`？——**不引 CLI 框架**，手写子命令分派保持零依赖）/ `App`：
  启动时序：`ConfigLoader`→`LogBootstrap`→`EventStore.open`→`SkillCatalog.scan`→`MCP links`→`SubagentManager`→创建主 `AgentRuntime`→网关注册→健康上报；优雅关停（SIGTERM→网关 drain→子进程树清理→SQLite checkpoint）。
- CLI：`run`（headless 网关守护）/ `agent --id <id>`（子 Agent 进程模式：只起 MCP stdio server + runtime）/ `health` / `doctor`（自检）/ `config validate`。

### 5.2 `io.mosire.main.gateway` —— 协议入口（薄适配）
1. **AdminREST**（jdk.httpserver，默认 127.0.0.1）：`GET /health`、`GET /api/status`（最低权限）、`GET /api/agents|tools|events`（分页、下游 guest/仅只读）、`POST /api/permissions/:permissionID`（OpenCode 式权限响应：`{response,remember?}`→ApprovalGate）。
2. **AG-UI server**（SSE 直出 + 最小事件子集兜底）：`POST /sessions`（RunAgentInput 接受）→ `GET /sessions/{id}/events`（`text/event-stream`）：RUN_STARTED → TEXT_MESSAGE_START/-CONTENT/…-END →（TOOL_CALL_*/STATE_*）→ RUN_FINISHED | RUN_ERROR；事件源于 EventBus 桥接（词汇表对齐）；Subagents 事件族暂缓（P2 观察 1.0）。
3. **A2A server**（自写绑定，D6；API 实测依据要点）：
   - `GET /.well-known/agent-card.json`：`AgentCard.builder()`（必填 name/description/version/capabilities/defaultInputModes/defaultOutputModes/skills/supportedInterfaces——record 已验证）；TCK 级就绪仅此一处；
   - `POST /a2a`：JSON-RPC 入站（body 解析用 `JsonUtil.OBJECT_MAPPER`（`org.a2aproject.sdk.jsonrpc.common.json.JsonUtil`：已注册 Part/A2AError/FileContent/OffsetDateTime 适配器）→ 密封 `A2AMessage` 分发（`A2ARequest` 按具体请求类）→ switch 路由：`message/send`（`A2AMethods` 常量）→`SendMessageResponse`；`messages/get|tasks/get|tasks/cancel|tasks/list`→对应 Response；方法未识别→`MethodNotFoundError`（-32601）；
   - 流式：`message/stream`、`tasks/subscribe` 走 SSE，每事件 `SendStreamingMessageResponse(id, StreamingEventKind)`（`JsonUtil.toJsonStreamingEvent` 给 `{"task":{...}}` 包装；Task/TaskStatusUpdateEvent（isFinal/isFinalOrInterrupted）/TaskArtifactUpdateEvent）；
   - 版本协商：Header `A2A-Version` 缺省 "0.3"→与 `supportedInterfaces` 主版本比对（规则照 A2AVersionValidator），不符→`VersionNotSupportedError`（-32009）；
   - Task 状态机参照 server-common `TaskManager.validateStateTransition` 语义：终态幂等覆盖允许、非终态→任意转移、A2AError→合成 FAILED；状态存储=EventStore（Task 快照）；
   - client 角色：官方 `Client.builder(card).withTransport(JSONRPCTransportConfigBuilder...)`（零 jakarta 已实测；`A2A.getAgentCard` 供发现）。
4. **MCP server**：主 Agent 的 ToolRegistry 经 `AgentToMcpServer` 暴露（stdio；供子 Agent/外部客户端）。**HTTP 形态（P2）**：2.0.1 官方服务端 HTTP 仅 servlet 实现（`HttpServletStreamableServerTransportProvider`），Spring WebMVC/WebFlux 传输已迁至 Spring AI（2.x 不再发布）→ 若需对外 HTTP MCP，自实现 `McpServerTransportProvider`（或 stateless 的 `McpStatelessServerTransport`）桥接 jdk.httpserver；JSON-RPC 信封可复用 `io.modelcontextprotocol.spec.McpSchema.JSONRPCRequest/Response/Notification/Error` + `McpError`，语义参照客户端参考实现 `HttpClientStreamableHttpTransport`。P0 不做。

### 5.3 `io.mosire.main.dist`
- shade 单 jar（`ServicesResourceTransformer`（SPI）；排除签名文件；minimizeJar 慎用）+ `java.options` 文档（AppCDS：`-XX:+UseAppCDS`/`-XX:SharedArchiveFile` 说明与生成脚本）；后续 jlink 选装说明。

## 六、数据模型与安全初始规范

> 出处：M2 实现过程的代码内注释 + 中期审计（见 `开发计划-中期.md`）。此处只登记**与本文前文表述不一致**的点，前文不改。

1. **A2A 方法名**（§5.2.3 写的 `message/send` 小写形态）：官方线实际为 CamelCase（`SendMessage`/`GetTask`/…，取自 `A2AMethods` 常量）；路由与错误映射照官方 `A2AServerRoutes.processRequest` 的 catch 链镜像。
